\begin{definition}[Bishop completion comparison square carrier]
\label{def:bishop-completion-comparison-square-carrier}
A $\BishopCompletionComparisonSquareUp$ carrier is a finite $\BHist$ packet
$$
X=(Q_0,Q_1,I_0,I_1,D,S,R,E,L,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $Q_0$ and $Q_1$ are the two dense-source faces, exposing the source data read by the induction-extension route and by the completion-interface route.
\item $I_0$ and $I_1$ are the two completion-interface faces, naming the $\BishopCompletionInductionUp$ extension read and the $\CauchyRealCompletionInterfaceUp$ boundary read over the same source faces.
\item $D$ is the shared $\DyadicRatCoreUp$ endpoint and tolerance ledger used by both faces before any Real seal is visible.
\item $S$ is the shared $\StreamNameUp$ finite-window row opened by the dyadic tolerance ledger.
\item $R$ is the shared $\RegSeqRatUp$ readback row attached to $D$ and $S$.
\item $E$ is the terminal $\RealUp$ seal reached only after the common route $D,S,R$ has been displayed.
\item $L$ is the square-commutation ledger, recording that both paths from $Q_0,Q_1$ through $I_0,I_1$ reach the same shared rows $D,S,R,E$ before any structural export.
\item $H$ records componentwise $\hsame$ transport for the dense-source faces, completion-interface faces, shared route rows, commutation ledger, replay, provenance, and local naming rows.
\item $C$ records displayed $\Cont$ replay of the square from each dense-source face through the shared route rows and the commutation ledger.
\item $P$ is the $\Pkg$ provenance over $\BishopCompletionComparisonSquareUp$, $\BishopCompletionInductionUp$, $\CauchyRealCompletionInterfaceUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\DyadicRatCoreUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\BishopCompletionComparisonSquareUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through $Q_0,Q_1,I_0,I_1,D,S,R,E,L,H,C,P,N$. It has no coordinate for ambient $\RealUp$ completeness, quotient streams, selected host limits, countable choice, host function equality, Lean verification, or bridge checking.
\end{definition}

\begin{theorem}[Bishop completion comparison square NameCert obligations]
\label{thm:bishop-completion-comparison-square-namecert-obligations}
For every accepted $\BishopCompletionComparisonSquareUp$ carrier
$$
X=(Q_0,Q_1,I_0,I_1,D,S,R,E,L,H,C,P,N),
$$
the local $\NameCert_{\BishopCompletionComparisonSquareUp}$ surface consists exactly of the following finite obligation rows:
\begin{enumerate}
\item carrier admission for the two dense-source faces, two completion-interface faces, shared dyadic ledger, finite windows, regular readback, Real seal, commutation ledger, transport, replay, provenance, and local naming rows;
\item dense-source visibility, requiring $Q_0$ and $Q_1$ to be displayed before either completion-facing face is read;
\item interface-face exactness, requiring $I_0$ to read the $\BishopCompletionInductionUp$ extension face and $I_1$ to read the $\CauchyRealCompletionInterfaceUp$ boundary face over the same displayed source data;
\item shared-route discipline, requiring both faces to consume the same $D,S,R,E$ route through $\DyadicRatCoreUp$, $\StreamNameUp$, $\RegSeqRatUp$, and $\RealUp$;
\item square-commutation, requiring $L$ to compare only the two displayed paths and their shared route rows;
\item structural non-escape, requiring $H,C,P,N$ to transport, replay, source, and name no row outside the displayed packet.
\end{enumerate}
No local obligation is stored outside these rows.
\end{theorem}
\begin{proof}
Carrier admission is projection from \autoref{def:bishop-completion-comparison-square-carrier}. The accepted packet displays exactly the two dense-source faces, two completion-interface faces, the shared route rows, and the structural rows.

Dense-source visibility is forced by the row order. Both completion-facing faces can be read only after $Q_0$ and $Q_1$ are visible, so neither path can introduce a hidden source representative.

The interface-face exactness clauses are the rows $I_0$ and $I_1$. The first reads the Bishop completion-induction extension face, and the second reads the Cauchy real completion-interface boundary face, both over the same displayed source data.

The shared-route and commutation clauses are the rows $D,S,R,E,L$. The dyadic ledger opens the finite windows, the regular readback consumes those windows, the Real seal is terminal, and the ledger $L$ compares only the two paths through those rows.

Finally $H,C,P,N$ add only transport, replay, provenance, and local naming. Since the carrier contains none of the excluded coordinates, the displayed rows exhaust the local NameCert surface.
\end{proof}

\begin{theorem}[Bishop completion comparison square commutes]
\label{thm:bishop-completion-comparison-square-commutes}

$$
\begin{gathered}

Q_0,Q_1 \longmapsto I_1 \longmapsto D,S,R,E \longmapsto L,H,C,P,N .
\end{gathered}
$$
Thus the two displayed paths commute at the local NameCert surface: each reaches the same dyadic tolerance ledger, finite StreamName windows, RegSeqRat readback, terminal Real seal, commutation ledger, transport, replay, provenance, and local name.
\end{theorem}
\begin{proof}
Project the accepted carrier. Both paths begin with the same dense-source faces $Q_0,Q_1$ and can inspect no completion-facing datum before those faces are displayed.

The upper path opens $I_0$, the Bishop completion-induction extension face. The lower path opens $I_1$, the Cauchy real completion-interface boundary face. By carrier admission, both faces are attached to the same source data and to the same shared route rows.

The shared route then forces the comparison. Both paths pass through $D,S,R,E$ before the commutation ledger can be read, so they reach the same dyadic tolerance, StreamName window, regular readback, and terminal Real-seal coordinates.

The ledger $L$ records exactly this comparison, while $H,C,P,N$ preserve, replay, source, and name it. No additional coordinate is present from which a second completion route could diverge.
