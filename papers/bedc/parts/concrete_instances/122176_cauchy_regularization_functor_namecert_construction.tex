Following Bishop--Bridges regular Cauchy completion, Kelley filter language, and Bourbaki uniform-space bookkeeping, the $\CauchyRegularizationFunctorUp$ packet records the finite route by which a displayed Cauchy-filter presentation is read as a regular Cauchy rational name before any Real or Completion consumer may use it. It sits after the Cauchy-filter surface of \autoref{ch:concrete-instances-cauchyfilter-namecert}, the finite observation windows of \autoref{ch:concrete-instances-streamname-namecert}, the regular rational readback of \autoref{ch:concrete-instances-regseqrat-namecert}, the dyadic tolerance ledger of \autoref{ch:concrete-instances-dyadicratcore-namecert}, and the terminal real-name seal of \autoref{ch:concrete-instances-real-namecert}. The packet is a handoff from filter data to regular Cauchy names; it does not quotient filters, select a limit, invoke countable choice, or claim ambient $\RealUp$ completeness.

\begin{definition}[Cauchy regularization functor carrier]
\label{def:cauchy-regularization-functor-carrier}
A $\CauchyRegularizationFunctorUp$ carrier is a finite $\BHist$ packet
$$
F=(A,W,R,D,E,H,K,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $A$ is the source row, either a $\CauchyFilterUp$ presentation or the refined $\CauchyFilterRegularizationUp$ source whose finite filter requests are being regularized.
\item $W$ is the $\StreamNameUp$ window row listing the finite request schedule used to inspect the source filter.
\item $R$ is the $\RegSeqRatUp$ readback row extracted from the source windows, recording the regular rational name seen by downstream consumers.
\item $D$ is the $\DyadicRatCoreUp$ tolerance ledger, carrying the dyadic precision, radius, comparison, and monotone budget rows used by the extraction.
\item $E$ is the terminal $\RealUp$ seal row, available only after $A,W,R,D$ have been displayed.
\item $H$ is the componentwise $\hsame$ transport row for the source, window, readback, tolerance ledger, real seal, provenance, and local name.
\item $K$ is the displayed $\Cont$ replay row, routing each accepted filter request through $W,D,R$ before the real seal is exposed.
\item $P$ records $\Pkg$ provenance over $\CauchyRegularizationFunctorUp$, $\CauchyFilterUp$, $\CauchyFilterRegularizationUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\DyadicRatCoreUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\CauchyRegularizationFunctorUp}$ row.
\end{enumerate}
The carrier has no coordinate for quotient equality of filters, a selected limit point, a countable-choice schedule, host real equality, or ambient completion of $\RealUp$.
\end{definition}

\begin{theorem}[Cauchy regularization functor obligation surface]
\label{thm:cauchy-regularization-functor-obligation-surface}
For every accepted $\CauchyRegularizationFunctorUp$ carrier $F=(A,W,R,D,E,H,K,P,N)$, the local $\NameCert_{\CauchyRegularizationFunctorUp}$ surface consists of the following finite rows:
\begin{enumerate}
\item source admission, requiring every input request to enter through the displayed $\CauchyFilterUp$ or $\CauchyFilterRegularizationUp$ row $A$;
\item window discipline, requiring every inspected request to be listed in the $\StreamNameUp$ row $W$ before it contributes to a regular name;
\item dyadic regularity, requiring the $\DyadicRatCoreUp$ ledger $D$ to supply the precision and tolerance budget for the readback;
\item regular rational extraction, requiring the $\RegSeqRatUp$ row $R$ to be produced from $A,W,D$ before any $\RealUp$ seal is visible;
\item real-seal nonselection, requiring the $\RealUp$ row $E$ to be consumed only as a terminal seal over the displayed regular name;
\item structural replay, requiring $H,K,P,N$ to transport, replay, source, and locally name exactly the displayed packet.
\end{enumerate}
No obligation row exports quotient filters, selected representatives, countable choice, host real equality, or ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Project the carrier rows of \autoref{def:cauchy-regularization-functor-carrier}. The source row is $A$, the finite inspection row is $W$, the tolerance row is $D$, the regular rational readback is $R$, and the terminal seal is $E$.

The NameCert obligation reads those rows in order. A filter request cannot reach $R$ until it has been scheduled by $W$ and budgeted by $D$, and the real seal $E$ is not available before the regular readback row is displayed.

Finally read the structural rows. The rows $H,K,P,N$ only transport, replay, source, and name the same packet, so they cannot add quotient filters, selected limits, countable choice, host real equality, or ambient completeness.
\end{proof}

\begin{theorem}[Cauchy regularization functor L10 handoff]
\label{thm:cauchy-regularization-functor-l10-handoff}
Every L10 Real or Completion consumer of an accepted $\CauchyRegularizationFunctorUp$ packet reaches the terminal Real boundary only through the displayed route
$$
\CauchyFilterUp\ \hbox{or}\ \CauchyFilterRegularizationUp,\quad
\StreamNameUp,\quad
\DyadicRatCoreUp,\quad
\RegSeqRatUp,\quad
\RealUp .
$$
Equivalently, the handoff from filter presentations to regular Cauchy names is exposed as finite $\StreamNameUp$ windows, $\DyadicRatCoreUp$ tolerance ledgers, $\RegSeqRatUp$ readbacks, and the terminal $\RealUp$ seal. A consumer asking for quotient filter equality, selected limits, countable choice, host real equality, or ambient completion has no row in the carrier.
\end{theorem}
\begin{proof}
Start with the source row $A$. By the obligation surface of \autoref{thm:cauchy-regularization-functor-obligation-surface}, each accepted request enters through the Cauchy-filter source and is then routed into the finite window $W$.

Next read the dyadic ledger and regular rational row. The ledger $D$ supplies the tolerance budget for every scheduled request, and the readback $R$ is the only regular Cauchy name exposed to downstream consumers.

The terminal seal $E$ is downstream from $A,W,D,R$. Since the carrier has no coordinate for quotient filters, selected limits, countable choice, host equality, or ambient completeness, Real and Completion consumers can use only the displayed L10 route.
\end{proof}
