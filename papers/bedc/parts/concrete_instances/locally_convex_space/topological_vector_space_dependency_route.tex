\begin{theorem}[Locally convex topological-vector-space dependency route]
\label{thm:locally-convex-space-topological-vector-space-route}
Every $\LocallyConvexSpaceUp$ consumer must read the $\TopVecSpaceUp$ linear-topology row of \autoref{ch:concrete-instances-topvecspace-namecert}, the $\ConvexSetUp$ neighbourhood row of \autoref{ch:concrete-instances-convexset-namecert}, and the $\FunctionalAnalysisUp$ continuity-facing row of \autoref{ch:concrete-instances-functionalanalysis-namecert} before treating the packet as locally convex. The route binds local convexity to displayed linear topology, convex neighbourhood, finite seminorm, continuity, transport, replay, provenance, and local naming rows; it is not a standalone host predicate for locally convex spaces.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:locally-convex-space-carrier}. Its rows $T,S,B$ already separate the topological-vector-space source, finite seminorm ledger, and convex balanced neighbourhood ledger.

The linear-topology row is read first through $\TopVecSpaceUp$. The convex-neighbourhood row is then read through $\ConvexSetUp$ as the displayed source for the neighbourhood evidence in $B$.

Only after those rows are visible may the $\FunctionalAnalysisUp$ consumer inspect continuity-facing data. Transport, replay, provenance, and local naming preserve the same finite route, so no independent locally convex host predicate, selected dual, Hahn--Banach row, or weak-star compactness row is exported.
\end{proof}
