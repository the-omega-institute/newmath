\begin{theorem}[SubspaceTopology topology forward route]
\label{thm:subspace-topology-topology-forward-route}
Every relative-open read of an accepted $\SubspaceTopologyUp$ packet first consumes the ambient $\TopologyUp$ indexed-open ledger of \autoref{ch:concrete-instances-topology-namecert}. Only after the ambient point classifier, indexed-open row, finite-intersection row, arbitrary-union row, admission row, relative-open row, restriction-exactness row, transport, replay, provenance, and local naming rows are visible may a $\MetricSubspaceUp$ or $\KelleyficationUp$ consumer use the induced topology. The route is a displayed topology-forward dependency; it does not export a host powerset topology, quotient subset equality, selected ambient representative, metric distance row, or independent open selector.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:subspace-topology-carrier}. The ambient topology row $X$ and admission row $A$ appear before the relative-open row $O$ and restriction-exactness row $R$, so every relative-open read starts with the same displayed $\TopologyUp$ source.

Use the NameCert obligations of \autoref{thm:subspace-topology-namecert-obligations}. They require the indexed-open ledger, finite-intersection row, arbitrary-union row, admission row, relative-open row, restriction-exactness row, transport, replay, provenance, and local naming rows to remain visible before a subspace open is public.

Apply the neighbour compatibility theorem, \autoref{thm:subspace-topology-neighbour-compatibility}, and the downstream Kelleyfication route, \autoref{thm:subspace-topology-downstream-kelleyfication-route}. These routes let $\MetricSubspaceUp$ and $\KelleyficationUp$ consume the induced topology only after the ambient $\TopologyUp$ ledger has been exposed. Hence the subspace packet supplies a topology-forward dependency and not an independent host topology.
\end{proof}
