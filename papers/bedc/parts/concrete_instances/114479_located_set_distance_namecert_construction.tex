\chapter{A Concrete Naming Certificate for $\LocatedSetDistanceUp$}
\label{ch:concrete-instances-located-set-distance-namecert}
\origin{human}

Following Bishop and Bridges on located subsets of metric spaces, the $\LocatedSetDistanceUp$ packet records the finite distance-to-a-located-set surface as displayed metric and real-valued ledger data. It sits over the located-subset carrier of \autoref{ch:concrete-instances-locatedset-namecert}, the distance-to-set surface of \autoref{ch:concrete-instances-distance-to-set-namecert}, the proximinal boundary of \autoref{ch:concrete-instances-proximinal-set-namecert}, the metric source of \autoref{ch:concrete-instances-metric-namecert}, and the terminal real-name seal of \autoref{ch:concrete-instances-real-namecert}. The packet names the finite route from an admitted ambient point and located subset to a $\RealUp$ distance read; it does not select a nearest point, quotient subset presentations, assert ambient compactness, or import full real completeness.

\begin{definition}[Located set distance carrier]
\label{def:located-set-distance-carrier}
A $\LocatedSetDistanceUp$ carrier is a finite $\BHist$ packet
$$
L=(X,A,D,R,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $X$ is the ambient $\MetricUp$ source row, including the admitted point classifier and distance observations.
\item $A$ is the $\LocatedSetUp$ row for the displayed subset, including its admission and locatedness comparisons.
\item $D$ is the $\DistanceToSetUp$ ledger row assigning each admitted ambient point and tolerance request a finite distance-to-subset comparison.
\item $R$ is the rational-window row through which the distance ledger is read before the terminal value is sealed.
\item $E$ is the $\RealUp$ seal row for the displayed distance value.
\item $H$ records componentwise $\hsame$ transport for the metric source, located subset, distance ledger, rational windows, real seal, provenance, and local naming rows.
\item $C$ records displayed $\Cont$ replay from point admission and located-subset reads to distance ledger, rational-window readback, real seal, and proximinal-facing requests.
\item $P$ is the $\Pkg$ provenance over $\MetricUp$, $\LocatedSetUp$, $\DistanceToSetUp$, $\ProximinalSetUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$ rows.
\item $N$ is the local $\NameCert_{\LocatedSetDistanceUp}$ row.
\end{enumerate}
The carrier has no coordinate for a chosen nearest point, quotient equality of subset presentations, host infimum, ambient compactness, or completeness of $\RealUp$.
\end{definition}

\begin{theorem}[Located set distance NameCert obligations]
\label{thm:located-set-distance-namecert-obligations}
For an accepted $\LocatedSetDistanceUp$ carrier $L=(X,A,D,R,E,H,C,P,N)$, the local $\NameCert_{\LocatedSetDistanceUp}$ surface consists exactly of carrier admission for the displayed metric source, located subset, distance ledger, rational-window row, real seal, transport, replay, provenance, and local naming; classifier stability under componentwise $\hsame$ transport; exact routing through the $\DistanceToSetUp$ ledger before the $\RealUp$ seal; compatibility with the $\LocatedSetUp$ locatedness rows; and non-escape from nearest-point selection, subset quotients, host infima, ambient compactness, and $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Project the carrier. The rows $X,A,D,R,E,H,C,P,N$ are the complete visible inventory, with the metric source and located-subset rows read before any distance value is available.

Use the sibling located-set and distance-to-set surfaces. The row $A$ supplies located-subset admission and comparison data, while $D$ supplies the distance-to-subset ledger over the same metric source $X$.

The rational-window and real-seal rows preserve that order. A consumer reaches $E$ only after $R$ has displayed the finite readback of $D$, and the support rows $H,C,P,N$ transport, replay, source, and name exactly this route.

Since no row stores a nearest-point choice, quotient subset equality, host infimum, compactness witness, or full real-completeness theorem, the local NameCert obligations are exhausted by the displayed carrier rows.
\end{proof}

\begin{theorem}[Located set distance Real-metric handoff]
\label{thm:located-set-distance-real-metric-handoff}
Every $\RealUp$-valued distance read exposed by an accepted $\LocatedSetDistanceUp$ carrier factors through the finite route
$$
X\longmapsto A\longmapsto D\longmapsto R\longmapsto E\longmapsto H,C,P,N .
$$
Thus the handoff from $\MetricUp$ to $\RealUp$ is a displayed distance ledger over a located subset, not a host infimum, quotient subset value, selected nearest point, ambient completion, or full real-completeness claim.
\end{theorem}
\begin{proof}
Start with the metric row $X$. It supplies the admitted ambient points and metric-distance observations used by the distance request.

Read the located subset row $A$ next. Locatedness makes the distance request a subset-facing comparison before any real-valued read is sealed.

Now project $D,R,E$. The ledger $D$ records the distance-to-set comparison, the rational-window row $R$ exposes its finite readback, and the terminal row $E$ seals that read as $\RealUp$ data.

The support rows $H,C,P,N$ add transport, replay, provenance, and local naming only for the same route. Hence the Real-metric handoff cannot bypass the finite ledger through a host infimum, nearest-point choice, quotient subset value, ambient completion, or real-completeness theorem.
\end{proof}

\begin{theorem}[Located set distance proximinal nonescape]
\label{thm:located-set-distance-proximinal-nonescape}
Any $\ProximinalSetUp$-facing consumer of an accepted $\LocatedSetDistanceUp$ carrier receives only the displayed $\MetricUp$, $\LocatedSetUp$, $\DistanceToSetUp$, rational-window, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, $\Pkg$, and local $\NameCert$ rows. A proximinal request may reuse the distance ledger, but it cannot extract a nearest point, a choice function selecting minimizers, quotient subset equality, compactness of the subset, or completeness of the ambient real line.
\end{theorem}
\begin{proof}
Project the proximinal-facing request through $P$ and $C$. The provenance names $\ProximinalSetUp$ only as a consumer boundary, and the continuation row exposes the same route $X,A,D,R,E$ before any proximinal read can inspect the packet.

Apply the NameCert obligations above. They force every distance value to pass through the located subset, distance ledger, rational-window readback, and real seal.

There is no carrier coordinate for a selected minimizer, a choice function, quotient subset equality, compactness of the subset, or ambient real completeness. Therefore proximinal consumers can reuse the finite distance surface but cannot escape to nearest-point data.
\end{proof}
