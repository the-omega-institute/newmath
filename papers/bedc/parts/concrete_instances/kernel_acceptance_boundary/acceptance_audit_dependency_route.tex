\begin{theorem}[Kernel acceptance boundary acceptance audit dependency route]
\label{thm:kernel-acceptance-boundary-acceptance-audit-dependency-route}
Every accepted-declaration exposure used to name a $\KernelAcceptanceBoundaryUp$ packet first factors through the $\KernelAcceptanceWitnessUp$ source row, and every forbidden-ancestry refusal used by the same packet first factors through the $\AxiomQueryLedgerUp$ refusal row. Thus the local boundary can be named only after the accepted-declaration route and the axiom-query route have both been displayed inside
$$
Q=(G,K,A,E,L,F,H,C,P,N).
$$
It does not supply kernel self-correctness, compiler correctness, hardware trust, or semantic adequacy of theorem names.
\end{theorem}
\begin{proof}
Project the accepted carrier of \autoref{def:kernel-acceptance-boundary-carrier}. The row $A$ is the accepted-declaration coordinate, and the row $F$ is the axiom-query refusal coordinate.

Apply \autoref{thm:kernel-acceptance-boundary-accepted-declaration-exposure}. It already exposes $A$ only together with $G,K,E,L,F,H,C,P,N$ and identifies the accepted-declaration source row with \autoref{ch:concrete-instances-kernelacceptancewitness-namecert}.

Now read the sibling dependency route. It states that the forbidden-ancestry refusal row is supplied by \autoref{ch:concrete-instances-axiomqueryledger-namecert} before local naming. Therefore $A$ and $F$ must both be present before the $\KernelAcceptanceBoundaryUp$ name can be consumed.

The final exclusions are inherited from the carrier and sibling route: neither dependency supplies kernel self-correctness, compiler correctness, hardware trust, or semantic adequacy.
\end{proof}
