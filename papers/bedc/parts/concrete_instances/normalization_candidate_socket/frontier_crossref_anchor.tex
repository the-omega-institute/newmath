\begin{theorem}[NormalizationCandidateSocket frontier cross-reference]
\label{thm:normalization-candidate-socket-frontier-crossref}
Every $\MetaCICNormalizationFrontierUp$ consumer of a $\NormalizationCandidateSocketUp$ packet must first pass through the candidate evidence rows, endpoint obstruction rows, socket rows, componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert$ row before any normalization endpoint is read. The route reaches the frontier consumer of \autoref{ch:concrete-instances-metacicnormalizationfrontier-namecert} and the candidate witness surface of \autoref{ch:concrete-instances-metacic-candidate-normalization-witness-namecert} only after those rows remain visible in the same finite packet.
\end{theorem}
\begin{proof}
Project the accepted socket packet. Its public coordinates already contain the candidate evidence rows, endpoint obstruction rows, socket rows, transport, replay, provenance, and local naming.

The frontier route then consumes those displayed rows through the sibling dependency named in \autoref{ch:concrete-instances-metacicnormalizationfrontier-namecert}. The witness route of \autoref{ch:concrete-instances-metacic-candidate-normalization-witness-namecert} is available only as part of the same displayed candidate evidence surface.

Since no carrier coordinate stores an already-read endpoint or an external normalization result, any endpoint-facing read must traverse the listed rows before it reaches the frontier consumer.
\end{proof}
