\begin{theorem}[Heron square-root sibling dependency lattice]
\label{thm:heron-square-root-sibling-dependency-lattice}
Every $\HeronSquareRootUp$ read that is exposed to a Real or Completion consumer must pass through the displayed Newton, regular-Cauchy, RegSeqRat, and Real siblings before the terminal square-root value is public. For a carrier
$$
H=(A,S,R,L,W,D,K,Q,E,T,C,P,N),

the lattice order first reads the positive radicand and seed rows, then the Heron recurrence and Newton provenance rows of \autoref{ch:concrete-instances-newtoniteration-namecert}, then the regular-Cauchy square-root route of \autoref{ch:concrete-instances-regular-cauchy-square-root-namecert}, then the $\RegSeqRatUp$ readback of \autoref{ch:concrete-instances-regseqrat-namecert}, and finally the terminal $\RealUp$ seal of \autoref{ch:concrete-instances-real-namecert}. The route exports no host square-root operation, quotient Real equality, selected completed limit, arbitrary trichotomy, countable choice, or ambient completeness theorem.
\end{theorem}

Project the accepted Heron carrier. The rows $A,S,R,L,W,D,K$ expose the positive source data, reciprocal ledger, visible Heron window, dyadic contraction estimate, and Newton provenance before any Real-facing row is available.

Apply the existing Heron handoff and sibling-route theorems. They place the $\NewtonIterationUp$ row on the same finite recurrence window, route the convergence read through $\RegularCauchySquareRootUp$, and force the $\RegSeqRatUp$ row $Q$ to be inspected before the terminal $\RealUp$ seal $E$.

The square-root boundary is therefore a consumer of the same displayed seal, not an independent oracle. Transport, replay, provenance, and local naming through $T,C,P,N$ preserve the order of the sibling rows, so the public Heron read remains inside the horizontal dependency lattice and cannot export any excluded host or quotient object.
\end{proof}
