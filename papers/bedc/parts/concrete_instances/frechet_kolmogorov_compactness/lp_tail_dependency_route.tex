\begin{theorem}[Frechet--Kolmogorov Lp-tail dependency route]
\label{thm:frechet-kolmogorov-compactness-lp-tail-route}
Every $\FrechetKolmogorovCompactnessUp$ consumer that reads compactness through Lp tails must first pass through the displayed sibling route
$$
\CompactMetricUp,\quad
\TotallyBoundedUp,\quad
\MetricCompletionUp,\quad
\mathsf{LpSpace}/\mathsf{LpTail},\quad
\BHist,\quad
\hsame,\quad
\Cont,\quad

$$
The exported compactness row is therefore a finite compact-metric, total-bounded, completion-facing, and Lp-tail dependency route, not an ambient compactness oracle, a selected subsequence, a selected subcover, or quotient completion equality.
\end{theorem}
\begin{proof}
Project the accepted carrier of \autoref{def:frechet-kolmogorov-compactness-carrier}. Its compactness-facing read already begins with the compact metric source and the finite-net budget, so any Lp-tail consumer must inherit those rows before reading a tail estimate.

Apply the total-bounded handoff of \autoref{thm:frechet-kolmogorov-compactness-total-bounded-handoff}. It keeps the finite-net row visible before the StreamName, RegSeqRat, and Real readbacks are inspected.

Now use the completion boundary and the existing sibling route of \autoref{thm:frechet-kolmogorov-compactness-orphan-route}. The Lp-space and Lp-tail rows can only be attached after the displayed $\MetricCompletionUp$ handoff has been routed through the same finite $\BHist/\Cont/\Pkg$ ledger.

Route exhaustion gives the stated dependency chain. No row in the carrier supplies an unrecorded compactness principle, selected subsequence, selected subcover, or quotient-completion equality, so the Lp-tail compactness export is exactly the displayed sibling route.
\end{proof}
