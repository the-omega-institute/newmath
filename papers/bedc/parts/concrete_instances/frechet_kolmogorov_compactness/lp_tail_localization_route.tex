\begin{theorem}[Frechet--Kolmogorov Lp-tail localization]
\label{thm:frechet-kolmogorov-compactness-lp-tail-localization}
Every $\FrechetKolmogorovCompactnessUp$ compactness read that localizes through an Lp-tail estimate consumes that estimate only after the compact-metric total-bounded route, tightness route, and Lp-tail dependency route have been displayed. Equivalently, the localized read factors through \autoref{thm:frechet-kolmogorov-compact-metric-total-bounded-dependency}, \autoref{thm:frechet-kolmogorov-tightness-route}, and \autoref{thm:frechet-kolmogorov-compactness-lp-tail-route}; it does not introduce an ambient compactness oracle, selected subsequence, selected subcover, quotient completion equality, or hidden Lp-tail selector.
\end{theorem}
\begin{proof}
Start with the compact-metric total-bounded route. It keeps the compact metric source and finite-net surface visible before a compactness-facing consumer may inspect downstream rows.

Next use the tightness route. Tightness and boundedness remain local dependency rows in the same finite ledger, so a tail estimate cannot bypass the displayed $\CompactMetricUp$, $\TotallyBoundedUp$, completion, readback, transport, replay, provenance, and local naming route.

Finally apply the Lp-tail dependency route. It attaches the $\mathsf{LpSpace}/\mathsf{LpTail}$ row only after the compact-metric, total-bounded, and completion-facing rows have been routed through the same finite $\BHist/\Cont/\Pkg$ ledger. Thus Lp-tail localization is a local factorization through the existing sibling routes, not a new compactness principle or choice-selected tail object.
\end{proof}
