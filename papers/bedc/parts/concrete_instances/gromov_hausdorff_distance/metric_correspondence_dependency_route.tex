\begin{theorem}[Gromov--Hausdorff metric-correspondence dependency]
\label{thm:gromov-hausdorff-metric-correspondence-dependency}
Any $\GromovHausdorffDistanceUp$ scalar read first consumes the sibling dependency route through $\MetricUp$ endpoint distances, $\CompactMetricUp$ finite-net rows, $\GromovHausdorffUp$ finite correspondence rows, $\HausdorffDistanceUp$ distortion comparison, and $\CompactMetricHyperspaceUp$ packaging before the local distance packet exports
$$
X,\quad Y,\quad R,\quad D,\quad H,\quad C,\quad P,\quad N .
$$
Thus the scalar route is a finite compact-metric and correspondence ledger: endpoint metrics and finite nets are visible before correspondence distortion is compared, hyperspace packaging is downstream of that comparison, and the local $\GromovHausdorffDistanceUp$ packet exports only the displayed rows.
\end{theorem}
\begin{proof}
Start with the carrier of \autoref{def:gromov-hausdorff-distance-carrier}. Its endpoint rows $X,Y$ expose compact metric data, so every scalar distance read begins with the underlying $\MetricUp$ distance rows and $\CompactMetricUp$ finite-net rows.

Apply the NameCert obligations of \autoref{thm:gromov-hausdorff-distance-namecert-obligations}. The correspondence stability and distortion symmetry rows force the read through the finite correspondence table $R$ and dyadic distortion ledger $D$ before any local scalar export is available.

Finally use the compact-metric handoff theorem \autoref{thm:gromov-hausdorff-distance-compact-metric-handoff}. It identifies the sibling-facing consumers as downstream of the same $X,Y,R,D,H,C,P,N$ route, so Hausdorff-distance comparison, Gromov--Hausdorff correspondence data, and compact-metric hyperspace packaging cannot bypass the displayed metric-correspondence dependency.
\end{proof}
