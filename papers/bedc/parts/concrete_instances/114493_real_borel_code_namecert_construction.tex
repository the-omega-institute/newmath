Following Bishop and Bridges and descriptive-set-theoretic Borel-code practice, the $\RealBorelCodeUp$ packet records constructive Borel codes over the existing $\RealUp$ naming surface as finite certificate data. It sits beside the regular-real carrier of \autoref{ch:concrete-instances-real-namecert}, the finite window route of \autoref{ch:concrete-instances-streamname-namecert}, the regular rational readback of \autoref{ch:concrete-instances-regseqrat-namecert}, and the dyadic endpoint arithmetic of \autoref{ch:concrete-instances-dyadicratcore-namecert}. The packet names code rows and their displayed interpretation schedules; it does not import host set equality, quotient equality of real names, impredicative sigma algebras, or a completed external powerset of $\RealUp$.

\begin{definition}[RealBorelCode carrier]
\label{def:real-borel-code-carrier}
A $\RealBorelCodeUp$ carrier is a finite $\BHist$ packet
$$
B=(I,S,R,D,T,U,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $I$ is the finite code-index ledger, listing exactly the inspected code rows and their immediate predecessor references.
\item $S$ is the $\StreamNameUp$ window schedule through which real-name consumers inspect only finite prefixes of the real input.
\item $R$ is the $\RegSeqRatUp$ readback row used to compare inspected windows with rational endpoint data.
\item $D$ is the $\DyadicRatCoreUp$ endpoint row, carrying displayed lower and upper dyadic rational bounds for basic real cylinders.
\item $T$ is the constructor-tag row. Its admitted tags are basic-cylinder, complement, and countable-coded union; the union tag stores only a displayed schedule of requested child rows, not an external subset family.
\item $U$ is the finite interpretation schedule saying how a basic cylinder reads $S,R,D$, how complement flips an already displayed child decision row, and how a countable-coded union exposes the finite child windows demanded by the current query.
\item $E$ is the $\RealUp$ seal boundary: every interpretation row reaches the real-name seal only through the displayed StreamName, RegSeqRat, and DyadicRatCore rows.
\item $H$ records componentwise $\hsame$ transport for code indices, StreamName windows, regular rational readback, dyadic endpoints, constructor tags, interpretation schedules, Real-seal rows, replay, provenance, and local naming.
\item $C$ records displayed $\Cont$ replay from a finite code-inspection request through $I,S,R,D,T,U,E,H,P,N$.
\item $P$ is the $\Pkg$ provenance over $\RealBorelCodeUp$, $\RealUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\DyadicRatCoreUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$ rows.
\item $N$ is the local $\NameCert_{\RealBorelCodeUp}$ row.
\end{enumerate}
The carrier predicate asserts exactly that these rows form one finite constructive Borel-code packet. It has no coordinate for host membership in an external set of reals, quotient equality of real names, countable choice over code branches, or an ambient Boolean algebra of subsets.
\end{definition}

\begin{theorem}[RealBorelCode NameCert obligations]
\label{thm:real-borel-code-namecert-obligations}
For every accepted $\RealBorelCodeUp$ carrier $B=(I,S,R,D,T,U,E,H,C,P,N)$, the local $\NameCert_{\RealBorelCodeUp}$ surface consists exactly of carrier admission for finite code indices, StreamName window exposure, RegSeqRat readback, DyadicRatCore endpoint comparison, constructor-tag admission, displayed interpretation schedules, Real-seal discipline, componentwise transport, displayed continuation replay, provenance, and local naming. Every code consumer must display
$$
I,S,R,D,T,U,E,H,C,P,N
$$
before it may read the interpretation of a code row on a $\RealUp$ name.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:real-borel-code-carrier}. The rows $I,S,R,D,T,U,E,H,C,P,N$ are the only accepted coordinates, so the NameCert obligations are read from those coordinates.

The basic-cylinder obligation is routed through $S,R,D$: a finite real-name window is compared with displayed dyadic endpoints by regular rational readback. Complement and countable-coded union use $T$ and $U$ to replay already displayed child rows or the finite child windows requested by the present query.

The Real-facing row $E$ is reached only after the StreamName, RegSeqRat, and DyadicRatCore rows have been displayed. The structural rows $H,C,P,N$ transport, replay, source, and locally name the same packet, leaving no further obligation outside the listed rows.
\end{proof}

\begin{theorem}[RealBorelCode cylinder stability]
\label{thm:real-borel-code-cylinder-stability}
Every basic-cylinder row of an accepted $\RealBorelCodeUp$ packet is stable under $\hsame$ transport of the displayed $\StreamNameUp$ windows, $\RegSeqRatUp$ readback rows, and $\DyadicRatCoreUp$ endpoints. If two inspected real-name windows are transported componentwise through the packet support, the same basic-cylinder decision schedule is replayed by $\Cont$ and the same constructor tag remains accepted.
\end{theorem}
\begin{proof}
Read the basic-cylinder branch of the constructor row $T$. Its interpretation schedule $U$ names only the inspected StreamName window, the regular rational readback row, and the dyadic endpoint comparison.

Apply the componentwise transport row $H$ to those three pieces. The transported window, readback, and endpoint rows remain attached to the same code index in $I$, and the local name row $N$ keeps the carrier coordinate fixed.

The replay row $C$ then re-executes the basic-cylinder schedule with the transported data. Since the packet contains no host real equality or external set membership coordinate, the stable output is exactly the displayed cylinder decision row.
\end{proof}

\begin{theorem}[RealBorelCode Real-seal nonescape]
\label{thm:real-borel-code-real-seal-nonescape}
Every $\RealUp$ read exported by an accepted $\RealBorelCodeUp$ packet factors through the finite route
$$
\StreamNameUp,\quad \RegSeqRatUp,\quad \DyadicRatCoreUp,\quad \RealUp .
$$
The complement and countable-coded union tags can replay only displayed child schedules and finite query windows before the terminal seal row $E$ is consumed. They export no quotient equality of real names, host set equality, countable-choice branch selector, external sigma algebra, or ambient powerset object.
\end{theorem}
\begin{proof}
Start from an accepted packet $B=(I,S,R,D,T,U,E,H,C,P,N)$. The only Real-facing row is $E$, and it is named after $S,R,D,T,U$ in the carrier.

For a basic-cylinder read, the route reaches $E$ through the inspected window, regular rational comparison, and dyadic endpoints. For a complement read, $U$ replays the displayed child schedule and flips only that local decision row.

For a countable-coded union read, the schedule exposes the finite child windows demanded by the current query. The row records no external infinite branch selector and no host subset family.

Thus every Real-facing consumer remains inside the displayed finite route. The refused quotient, host equality, choice, sigma-algebra, and powerset objects have no coordinate in the carrier.
\end{proof}
