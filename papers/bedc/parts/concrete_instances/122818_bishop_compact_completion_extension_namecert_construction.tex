\begin{definition}[Bishop compact completion-extension carrier]
\label{def:bishop-compact-completion-extension-carrier}
A $\BishopCompactCompletionExtensionUp$ carrier is a finite $\BHist$ packet
$$
E=(K,C,U,F,S,R,D,Q,L,H,T,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $K$ is the $\CompactMetricUp$ row whose compact data are read only
through displayed finite-net or total-boundedness witnesses.
\item $C$ is the $\CompletionUp$ row naming the source and target completion
surfaces used by the extension read.
\item $U$ is the $\UniformContinuousExtensionUp$ row carrying the source
graph, finite uniform modulus, target convergence handoff, and separated
uniqueness ledger.
\item $F$ is the $\CauchyCompletionFunctorUp$ row recording the functorial
source-to-completion and completion-consumer routes for the same Cauchy data.
\item $S$ is the $\StreamNameUp$ finite-window row through which compact
source names and completion names are inspected.
\item $R$ is the $\RegSeqRatUp$ regular-rational readback row attached to the
same windows.
\item $D$ is the $\DyadicRatCoreUp$ tolerance ledger controlling compact-net
mesh size, Cauchy radius, and uniform-modulus budget.
\item $Q$ is the $\RealUp$ seal row reached only after $S,R,D$ and the
completion-extension rows have been displayed.
\item $L$ is the finite compact-net ledger: for each displayed dyadic
tolerance it lists net centers, incidence rows, image-window rows, and the
extension-uniqueness comparison row served by $K,U,F$.
\item $H$ records componentwise $\hsame$ transport for $K,C,U,F,S,R,D,Q,L,P,N$.
\item $T$ records displayed $\Cont$ replay from a compact-net request through
the completion-extension route.
\item $P$ is the $\Pkg$ provenance over $\BishopCompactCompletionExtensionUp$,
$\CompactMetricUp$, $\CompletionUp$, $\UniformContinuousExtensionUp$,
$\CauchyCompletionFunctorUp$, $\StreamNameUp$, $\RegSeqRatUp$,
$\DyadicRatCoreUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\BishopCompactCompletionExtensionUp}$ row.
\end{enumerate}
The carrier has no coordinate for open-cover compactness, selected limits,
quotient completion equality, countable choice, host function equality, or
ambient $\RealUp$ completeness.
\end{definition}

\begin{theorem}[Bishop compact completion-extension NameCert obligations]
\label{thm:bishop-compact-completion-extension-namecert-obligations}
For every accepted $\BishopCompactCompletionExtensionUp$ carrier
$$
E=(K,C,U,F,S,R,D,Q,L,H,T,P,N),
$$
the local $\NameCert_{\BishopCompactCompletionExtensionUp}$ surface consists
exactly of carrier admission for the compact-metric row, completion row,
uniform-extension row, Cauchy-completion-functor row, finite stream windows,
regular-rational readback, dyadic tolerance ledger, terminal Real seal,
finite compact-net ledger, componentwise transport, displayed replay,
provenance, and local naming. Every completion-extension read must display
the finite-net row $L$ and the uniqueness route supplied by $U$ and $F$ before
it exposes a completed value.
\end{theorem}
\begin{proof}
Project the carrier of
\autoref{def:bishop-compact-completion-extension-carrier}. Its coordinates are
exactly $K,C,U,F,S,R,D,Q,L,H,T,P,N$, so carrier admission and local naming can
inspect only those rows.

Read the compact side next. The row $K$ supplies compact metric data only
through displayed finite-net evidence, while $L$ records the tolerance-indexed
net centers, incidence rows, and image windows used by the extension read.

Read the completion side through $C,U,F$. The completion row names the source
and target completion surfaces, the uniform-extension row carries the finite
modulus and separated uniqueness ledger, and the Cauchy-completion-functor row
keeps the source-to-completion and completion-consumer routes attached to the
same Cauchy data.

Finally read the numerical corridor $S,R,D,Q$ and the structural rows $H,T,P,N$.
Finite windows, regular-rational readback, and dyadic budgets precede the
terminal Real seal, while transport, replay, provenance, and local naming
preserve the same packet. No excluded compactness, choice, quotient, host
equality, or ambient completeness principle is a carrier coordinate.
\end{proof}

\begin{theorem}[Bishop compact completion-extension finite-net handoff]
\label{thm:bishop-compact-completion-extension-finite-net-handoff}
Every completion-facing consumer of an accepted
$\BishopCompactCompletionExtensionUp$ carrier factors through the finite route
$$
\CompactMetricUp,\ \CompletionUp,\ \UniformContinuousExtensionUp,\ 
\CauchyCompletionFunctorUp,\ \StreamNameUp,\ \RegSeqRatUp,\ 
\DyadicRatCoreUp,\ \RealUp
$$
as displayed by $K,C,U,F,S,R,D,Q,L,H,T,P,N$. In particular, compactness enters
only through the finite compact-net ledger $L$, and completion-extension
uniqueness enters only through the rows $U$ and $F$ before the terminal
$\RealUp$ seal is consumed.
\end{theorem}
\begin{proof}
Start with the NameCert obligations of
\autoref{thm:bishop-compact-completion-extension-namecert-obligations}. They
force every accepted read to expose the compact row, completion row,
uniform-extension row, Cauchy functor row, finite windows, rational readback,
dyadic ledger, compact-net ledger, and structural rows.

The compact handoff is finite. For each requested dyadic tolerance, $L$ lists
the net centers and incidence rows read from $K$, then records the image
windows that the extension row may inspect. Thus the consumer receives
compact-net rows, not an open-cover subcover principle.

The extension handoff is unique only inside the displayed completion route.
Rows $U$ and $F$ say that two extension reads agreeing on the same source
completion windows and uniform-modulus data have the same separated target
read. This is a finite uniqueness ledger, not quotient completion equality and
not host function equality.

The Real-facing corridor then reads $S,R,D,Q$. The terminal seal $Q$ is reached
only after the stream windows, regular-rational readback, dyadic budgets,
compact-net ledger, and completion-extension rows have all been displayed, so
the handoff exports no selected limit, countable choice schedule, or ambient
$\RealUp$ completeness.
\end{proof}
