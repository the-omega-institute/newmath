\begin{theorem}[Real function-space NameCert obligations]\label{thm:real-function-space-namecert-obligations}
For every accepted $\RealFunctionSpaceUp$ carrier $F=(X,W,A,R,E,M,H,C,P,N)$, the local $\NameCert_{\RealFunctionSpaceUp}$ surface consists exactly of the following five obligation rows:
\begin{enumerate}
\item carrier admission for the displayed source window, graph-window schedule, continuous-map row, regular readback, Real seal, pointwise metric, transport, replay, provenance, and local naming rows;
\item graph-window exactness, requiring every inspected input/output pair to pass through $X,W,A$ before any output value is read;
\item output seal nonescape, requiring $R$ and $E$ to remain downstream of the same displayed graph-window schedule;
\item pointwise comparison stability, requiring $M$ to compare function-space reads only through finite pointwise windows and componentwise $\hsame$ transport;
\item ledger rows for displayed $\Cont$ replay, $\Pkg$ provenance, and the local $\NameCert$ name.
\end{enumerate}
No accepted obligation row is stored outside $X,W,A,R,E,M,H,C,P,N$.
\end{theorem}
\begin{proof}
Project the accepted carrier of \autoref{def:real-function-space-carrier}. The mathematical rows are $X,W,A,R,E,M$, and the structural rows are $H,C,P,N$.

The graph-window and output-seal obligations are read in order. A consumer first sees the source window $X$, graph-window schedule $W$, and continuous-map row $A$; only then can it open the regular readback $R$ and terminal real seal $E$.

The comparison obligation is read through $M$. Since $M$ stores only finite pointwise windows, it cannot provide host function extensionality, quotient equality, a completed function space, a selected pointwise limit, countable choice, or ambient completeness.

Finally $H,C,P,N$ transport, replay, source, and name the same displayed route. Thus the five listed obligation rows exhaust the local certificate surface.
\end{proof}
