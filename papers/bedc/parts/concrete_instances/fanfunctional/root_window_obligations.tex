\begin{theorem}[FanFunctional finite-window coverage]
\label{thm:fan-functional-finite-window-coverage}
Every accepted $\FanFunctionalUp$ finite-window packet exposes a finite Cantor-prefix window before any $\UniformModulusUp$ row is read. Concretely, for the carrier $\Omega=(B,Q,F,D,U,T,K,W,H,R,P,N)$ of \autoref{def:fanfunctional-finite-window-carrier}, the rows $B,Q,W$ display the Cantor-prefix windows consumed by the root read before the fan bar row $F$, the finite depth row $D$, or the modulus row $M$ of the root-schema consumer is exported. The coverage route is the displayed $\CantorSpaceUp$, $\FanTheoremUp$, $\UniformContinuityUp$, $\CompactMetricUp$, and $\UniformModulusUp$ path, not a selected infinite branch, host functional, open-cover compactness proof, or countable-choice schedule.
\end{theorem}
\begin{proof}
Project the finite-window carrier of \autoref{def:fanfunctional-finite-window-carrier}. Its Cantor-facing coordinates are $B,Q,W$, and \autoref{thm:fanfunctional-cantor-window-obligation} requires those finite rows to be visible before the fan bar, depth, or local naming rows are consumed.

Next use the root schema carrier and root NameCert acceptance, \autoref{thm:fanfunctional-root-schema-carrier} and \autoref{thm:fanfunctional-root-namecert-acceptance}. These results keep the compact and uniform-modulus consumers on the same $B,Q,F,D,U,T,K,W,H,R,P,N$ route.

Finally apply the Cantor-window coverage obligations in the spine. The displayed CantorSpace, FanTheorem, UniformContinuity, CompactMetric, and UniformModulus rows exhaust the finite-window surface, so no consumer may replace them by an infinite branch selector, host functional, open-cover compactness proof, or countable-choice schedule.
\end{proof}

\begin{theorem}[FanFunctional modulus-window monotonicity]
\label{thm:fan-functional-modulus-window-monotonicity}
The $\UniformModulusUp$ row extracted from an accepted $\FanFunctionalUp$ finite-window packet is read through the finite bar-depth ledger $F,D$ and never through an infinite branch selector. If a later modulus request asks for a stronger displayed tolerance row, its witness-window read refines the earlier read only by extending the finite Cantor-prefix window already displayed in $B,Q,W$ and by reusing the same $\FanTheoremUp$, $\UniformContinuityUp$, $\CompactMetricUp$, $\UniformModulusUp$, $\hsame$, $\Cont$, $\Pkg$, and $\NameCert$ route.
\end{theorem}
\begin{proof}
Start with \autoref{thm:fanfunctional-root-bar-depth-exactness}. It places the bar-depth row $D$ after the Cantor-prefix and fan rows and before any uniform-modulus or uniform-continuity row is consumed.

Use \autoref{thm:fanfunctional-root-modulus-window-coverage} to identify the witness-window surface. A stronger displayed tolerance can only enlarge or refine the finite witness windows already carried by $B,Q,W$ under the same finite depth row.

Finally apply \autoref{thm:fanfunctional-uniform-modulus-obligation} together with \autoref{thm:fanfunctional-root-namecert-acceptance}. The extracted modulus row is therefore read through $F,D,U,T,W,H,R,P,N$ and the compact finite-prefix row $K$, with no coordinate for an infinite branch selector or host compactness argument.
\end{proof}

\begin{theorem}[FanFunctional Cantor-prefix nonescape]
\label{thm:fan-functional-cantor-prefix-nonescape}
All Cantor-prefix consumers of an accepted $\FanFunctionalUp$ finite-window packet remain inside the displayed route
$$
C,F,B,D,W,M,H,K,P,N .
$$
Equivalently, a consumer may read Cantor prefixes, fan bar data, retained prefix windows, finite depth, witness windows, modulus output, componentwise transport, compact finite-prefix support, provenance, and the local $\NameCert$ row, but it cannot escape to a selected infinite branch, host functional, open-cover compactness proof, countable-choice selector, or ambient Real-completeness witness.
\end{theorem}
\begin{proof}
Begin with the carrier and NameCert obligation theorem in the spine, \autoref{def:fanfunctional-finite-window-carrier} and \autoref{thm:fanfunctional-root-namecert-acceptance}. They display the Cantor, fan, witness, modulus, compact, transport, replay, provenance, and local naming rows before any root consumer can accept the packet.

Next apply \autoref{thm:fanfunctional-cantor-window-obligation} and \autoref{thm:fanfunctional-compactmetric-consumer-obligation}. The Cantor rows are finite prefix windows, and the compact-metric consumer receives only the displayed finite-net support attached to those prefixes.

Finally use \autoref{thm:fanfunctional-choice-free-nonescape-obligations}. Since selected branches, host functionals, open-cover compactness proofs, countable-choice selectors, and ambient Real-completeness witnesses have no carrier coordinate, every Cantor-prefix consumer stays inside the displayed $C,F,B,D,W,M,H,K,P,N$ route.
\end{proof}
