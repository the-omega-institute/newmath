It sits over the metric carrier of \autoref{ch:concrete-instances-metric-namecert}, the separable-metric source of \autoref{ch:concrete-instances-separablemetric-namecert}, the complete-metric boundary of \autoref{ch:concrete-instances-completemetric-namecert}, the completion handoff of \autoref{ch:concrete-instances-metriccompletion-namecert}, the terminal real-distance seal of \autoref{ch:concrete-instances-real-namecert}, and the larger Urysohn finite-extension packet of \autoref{ch:concrete-instances-urysohn-universal-metric-namecert}. \begin{definition}[Urysohn rational metric carrier]
\label{def:urysohn-rational-metric-carrier}
A $\UrysohnRationalMetricUp$ carrier is a finite $\BHist$ packet
$$
Q=(M,S,D,F,A,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $M$ is the $\MetricUp$ or $\MetricSpaceUp$ source row whose finite support points and support distances are inspected.
\item $S$ is the $\SeparableMetricUp$ finite support schedule naming exactly the support points used by the extension request.
\item $D$ is the rational distance table row. It records the already displayed support distances and the proposed rational distance from the new point to each support point.
\item $F$ is the finite rational Katetov request row. It lists the triangle and reverse-triangle inequalities checked for each displayed support pair.
\item $A$ is the admission ledger row. It records that every inequality in $F$ is verified using only the rational table $D$ and the source metric row $M$.
\item $E$ is the one-point extension handoff row. It allows a consumer to read the rational extension request after $M,S,D,F,A$ have been exposed.
\item $H$ records componentwise $\hsame$ transport for the source metric, support schedule, rational table, Katetov request, admission ledger, extension handoff, replay, provenance, and local name.
\item $C$ records displayed $\Cont$ replay for the same finite request and admission rows.
\item $P$ is the $\Pkg$ provenance over $\UrysohnRationalMetricUp$, $\MetricUp$, $\MetricSpaceUp$, $\SeparableMetricUp$, $\RealUp$, rational finite metric tables, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\UrysohnRationalMetricUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through $M,S,D,F,A,E,H,C,P,N$. It has no coordinate for a host universal metric space, a selected completion point, quotient completion equality, an arbitrary countable extension schedule, choice, Lean verification, a standard bridge, or ambient real completeness.
\end{definition}

\begin{theorem}[Urysohn rational metric NameCert obligations]
\label{thm:urysohn-rational-metric-namecert-obligations}
For every accepted $\UrysohnRationalMetricUp$ carrier
$$
Q=(M,S,D,F,A,E,H,C,P,N),
$$
the local $\NameCert_{\UrysohnRationalMetricUp}$ surface consists exactly of six finite obligation rows:
\begin{enumerate}
\item carrier admission for the metric source, finite support schedule, rational distance table, finite Katetov request, admission ledger, extension handoff, transport, replay, provenance, and local name;
\item common-source discipline, requiring $S,D,F,A$ to be read over the same metric source row $M$;
\item rational support visibility, requiring every distance in $D$ to be attached to a support point named by $S$;
\item Katetov inequality exposure, requiring $F$ and $A$ to display each triangle and reverse-triangle budget over the rational table;
\item extension-handoff order, requiring $E$ to be consumed only after $M,S,D,F,A$ have been exposed;
\item nonescape, excluding host Urysohn spaces, quotient completion equality, arbitrary extension chains, selected completion points, countable choice, Lean verification, bridge credentials, and ambient $\RealUp$ completeness.
\end{enumerate}
No Urysohn rational metric obligation is stored outside these rows.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:urysohn-rational-metric-carrier}. The tuple $M,S,D,F,A,E,H,C,P,N$ is the whole public surface, so carrier admission is exactly admission of those rows.

The common-source and support-visibility obligations follow from $M,S,D$. The support schedule names the finite points, and the rational distance table is read only over those points and the same source metric row.

The Katetov obligation is recorded by $F$ and $A$. The request row lists the triangle and reverse-triangle comparisons, while the admission ledger records that each comparison has been checked against the rational table.

Finally $E,H,C,P,N$ preserve only that displayed finite route. Since none of the carrier coordinates stores a host universal space, quotient completion equality, countable extension chain, selected completion point, choice functional, Lean credential, bridge credential, or ambient completeness theorem, the listed rows exhaust the local NameCert surface.
\end{proof}

\begin{theorem}[Urysohn rational metric one-point extension]
\label{thm:urysohn-rational-metric-one-point-extension}
Every finite rational one-point extension request accepted by a $\UrysohnRationalMetricUp$ carrier factors through
$$
\MetricUp \longmapsto \SeparableMetricUp \longmapsto D,F,A \longmapsto E .
$$
The request is therefore a displayed rational Katetov route over the current finite support, not a point selected from a universal metric space, a quotient class in a completed space, or an ambient $\RealUp$ limit.
\end{theorem}
\begin{proof}
Begin with the metric source row $M$ and finite support schedule $S$. They expose the only support points and support distances available to the extension request.

Read the rational table $D$ next. It supplies the proposed rational distances from the new point to the displayed support and records the already visible support-distance comparisons.

The rows $F$ and $A$ then check the finite Katetov inequalities. Each compatibility budget is a rational row attached to the displayed support table, so no hidden real-completion datum is introduced.

The handoff row $E$ exports only this finite rational route. Host universal metric spaces, quotient completion representatives, selected completion points, arbitrary countable extension chains, choice functionals, and ambient Real completeness remain outside the packet.
\end{proof}
