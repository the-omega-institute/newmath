\begin{theorem}[Bishop real-line interface regular-completion dependency route]
\label{thm:bishop-real-line-interface-regular-completion-dependency-route}
Every $\BishopRealLineInterfaceUp$ consumer that reads a completion-facing real-line source through ordered Cauchy-group data must first pass through the $\BishopRegularCauchyCompletionUp$ packet of \autoref{ch:concrete-instances-bishop-regular-cauchy-completion-namecert}. The route consumes the displayed dyadic endpoint and tolerance ledger, finite $\StreamNameUp$ windows, $\RegSeqRatUp$ regular readback, common-tail modulus data, terminal $\RealUp$ seal, and componentwise structural rows from that completion packet, then threads the ordered Cauchy-group rows for addition, order, and order-compatible completion through the interface rows $D,W,R,E,Q,H,C,P,N$.

Thus the Bishop real-line interface depends on regular Cauchy completion as a finite L10 source together with ordered Cauchy-group structure. It does not import a selected completed representative, quotient equality of real names, trichotomy, host real equality, countable choice, metric completeness, open-cover compactness, or ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Start with the completion-facing route of \autoref{ch:concrete-instances-bishop-regular-cauchy-completion-namecert}. Its accepted packet exposes dyadic tail data, finite stream observations, regular Cauchy readback, common-tail comparison, Real-seal handoff, componentwise transport, continuation replay, provenance, and local naming before any completion consumer may read it.

Next use the four-object route of \autoref{thm:bishop-real-line-interface-four-object-route}. The interface can read the completion packet only through the displayed $\DyadicRatCoreUp$, $\StreamNameUp$, $\RegSeqRatUp$, and $\RealUp$ rows, with Cauchy-equivalence comparison and structural rows remaining downstream.

The ordered Cauchy-group data supplies addition, order, and order-compatible completion rows after the same finite real-line source has been displayed. Those rows refine how the source is consumed; they do not add a host completed object or a second equality principle.

Finally apply nonescape from \autoref{thm:bishop-real-line-interface-nonescape}. Since the interface carrier has no coordinate for selected representatives, quotient equality, trichotomy, host equality, choice, metric completeness, open-cover compactness, or ambient Real completeness, none of those objects can enter through the regular-completion dependency route.
\end{proof}
