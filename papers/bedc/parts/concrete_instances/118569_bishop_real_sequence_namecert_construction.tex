\begin{definition}[Bishop real sequence carrier]
\label{def:bishop-real-sequence-carrier}
A $\BishopRealSequenceUp$ carrier is a finite $\BHist$ packet
$$
S=(W,R,D,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $W$ is the $\StreamNameUp$ window family indexed by the visible $\mathsf{UnaryHistory}$ entries requested by the consumer.
\item $R$ is the $\RegSeqRatUp$ readback row for those windows, recording the regular rational approximants exposed at each inspected index.
\item $D$ is the $\DyadicRatCoreUp$ tolerance ledger attached to the same finite window request.
\item $E$ is the terminal $\RealUp$ seal row, available only after $W,R,D$ have been displayed.
\item $H$ records componentwise $\hsame$ transport for the window family, readback row, tolerance ledger, terminal seal, provenance, and local name.
\item $C$ records displayed $\Cont$ replay from a sequence-entry request through $W,R,D,E$ and then to the structural rows.
\item $P$ is the $\Pkg$ provenance over $\BishopRealSequenceUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\DyadicRatCoreUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\BishopRealSequenceUp}$ row.
\end{enumerate}
No carrier coordinate stores a selected limit, quotient sequence equality, countable-choice schedule, host real equality, or ambient $\RealUp$ completeness theorem.
\end{definition}

\begin{theorem}[Bishop real sequence pointwise stability]
\label{thm:bishop-real-sequence-pointwise-stability}
Let $S=(W,R,D,E,H,C,P,N)$ and $S'=(W',R',D',E',H',C',P',N')$ be accepted $\BishopRealSequenceUp$ carriers. If the displayed $\StreamNameUp$ windows, $\RegSeqRatUp$ readback rows, $\DyadicRatCoreUp$ tolerance ledgers, and terminal $\RealUp$ seal rows agree componentwise under the visible $\hsame$ transports, then every inspected $\mathsf{UnaryHistory}$ entry has the same exported real-name row in $S$ and $S'$.
\end{theorem}
\begin{proof}
Project both carriers through \autoref{def:bishop-real-sequence-carrier}. The only entry-facing coordinates are $W,R,D,E$, and each is transported by the displayed rows $H,H'$.

For a fixed inspected $\mathsf{UnaryHistory}$ entry, read the stream window first. The readback row $R$ is attached to that same finite window, and the tolerance row $D$ records the dyadic budget used by the readback.

The terminal seal $E$ is available only after those rows have been displayed. Since the corresponding rows agree componentwise under $\hsame$, the replay routes $C,C'$ export the same real-name row for the inspected entry.
\end{proof}

\begin{theorem}[Bishop real sequence tail window]
\label{thm:bishop-real-sequence-tail-window}
Every accepted $\BishopRealSequenceUp$ consumer that asks for a finite tail window must first display the $\StreamNameUp$ windows indexed by the requested $\mathsf{UnaryHistory}$ tail, then the matching $\RegSeqRatUp$ readback row, then the $\DyadicRatCoreUp$ tolerance ledger, before any terminal $\RealUp$ seal can be read.
\end{theorem}
\begin{proof}
Begin with the consumer request and project the carrier inventory. The request can reach only the displayed rows $W,R,D,E,H,C,P,N$.

The window row $W$ fixes the finite tail segment being inspected. The readback row $R$ is tied to this window, and the tolerance row $D$ supplies the dyadic budget for the same indices.

Only after this finite surface is visible may the route read $E$. The structural rows $H,C,P,N$ preserve and name the route without adding a selected tail limit, quotient sequence representative, or choice schedule.
\end{proof}
