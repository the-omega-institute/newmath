\begin{theorem}[CauchyRealSpread sibling dependency]
\label{thm:cauchy-real-spread-sibling-dependency}
Every accepted $\CauchyRealSpreadUp$ read that exports a Real-and-Completion spread packet consumes the sibling route through \autoref{ch:concrete-instances-streamname-namecert}, \autoref{ch:concrete-instances-regseqrat-namecert}, \autoref{ch:concrete-instances-real-namecert}, \autoref{ch:concrete-instances-cauchyfilter-namecert}, and \autoref{ch:concrete-instances-completion-namecert}. The consumer must first read the $\StreamNameUp$ finite windows, then the $\RegSeqRatUp$ regular readback, then the terminal $\RealUp$ seal, then the $\CauchyFilterUp$ filter-facing route, and only then the $\CompletionUp$ handoff before any spread packet is public. This route exports no selected branch, quotient stream equality, selected Cauchy representative, countable choice, or ambient Real-completeness coordinate.
\end{theorem}
\begin{proof}
Project the accepted $\CauchyRealSpreadUp$ carrier of \autoref{def:cauchy-real-spread-carrier}. Its public read rows expose finite windows through $\StreamNameUp$, regular rational readback through $\RegSeqRatUp$, and a terminal $\RealUp$ seal before any downstream completion-facing consumer is available.

The filter and completion siblings are reached only after those displayed rows have been consumed. The $\CauchyFilterUp$ route reads the same finite StreamName and RegSeqRat data as a filter-facing boundary, and the $\CompletionUp$ handoff receives only that displayed filter boundary together with the structural rows $H,C,P,N$.

Thus the Real-and-Completion spread packet is a horizontal dependency route through the named sibling chapters. Since no row stores an infinite selected branch, quotient stream equality, a selected Cauchy representative, countable choice, or ambient Real completeness, the exported packet has exactly the displayed sibling dependencies.
\end{proof}
