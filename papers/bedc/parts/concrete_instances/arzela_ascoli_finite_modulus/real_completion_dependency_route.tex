\begin{theorem}[Arzela--Ascoli Real-and-completion dependency route]
\label{thm:arzela-ascoli-finite-modulus-real-completion-dependency-route}
Every Real-and-completion-facing read from an accepted $\ArzelaAscoliFiniteModulusUp$ packet consumes the route through finite modulus data, finite $\StreamNameUp$ windows, $\RegSeqRatUp$ handoff rows, and $\DyadicRatCoreUp$ tolerance rows before the terminal $\RealUp$ seal is visible. The route therefore reads \autoref{ch:concrete-instances-real-namecert}, \autoref{ch:concrete-instances-regseqrat-namecert}, \autoref{ch:concrete-instances-streamname-namecert}, and \autoref{ch:concrete-instances-dyadicratcore-namecert} as row-level dependencies, not as a selected limit, quotient stream equality, countable-choice schedule, host function-space compactness, or ambient $\RealUp$ completeness theorem.
\end{theorem}
\begin{proof}
Project the accepted carrier of \autoref{def:arzela-ascoli-finite-modulus-carrier}. The finite modulus row $M$, window row $W$, regular readback row $R$, and terminal seal row $E$ are part of the displayed packet.

Read the Real-and-completion route in order. The finite modulus controls which family values may be compared, the $\StreamNameUp$ row bounds the inspected windows, the $\RegSeqRatUp$ row supplies the regular rational handoff, and the $\DyadicRatCoreUp$ tolerance cells keep each read tied to the same finite precision ledger.

Only after those rows have been displayed may the consumer see the $\RealUp$ seal. Since none of the carrier rows contains a selected limit, quotient stream equality, countable-choice schedule, host function-space compactness, or ambient completeness coordinate, the dependency remains a finite row-level route.
\end{proof}
