\begin{theorem}[Apophatic gate question derivation route]
\label{thm:apophatic-gate-question-derivation-route}
Every accepted $\ApophaticGateQuestionUp$ gate-question read is generated by socket exposure, named refusal compatibility, the audit row, kind and source readback, componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, and the local $\NameCert$ row. In carrier notation the route is exactly
$$
S,Q,R,A,H,C,P,N.
$$
It is not generated by a host complete apophatic object, a hidden outside-supply witness, an unmarked selector, quotient collapse, proposition-extensionality collapse, or a detached host gate answer.
\end{theorem}
\begin{proof}
Start with the public NameCert package. It identifies the exported gate-question surface with the displayed carrier rows and the local certificate obligations, so a public read has no coordinate outside $S,Q,R,A,H,C,P,N$.

Read the source side first. Socket-name dependency and source-gate exactness force $S$ and $Q$ to be exposed through the visible $\ApophaticSocketUp$ or $\ApophaticNameUp$ route before any audit readback can be consumed.

Now read the refusal and audit side. Refusal nonescape coverage and audit route exactness bind $R$ and $A$ to the same packet, while $H,C,P,N$ transport, replay, source, and name the route. The excluded host object, outside-supply witness, selector, quotient, proposition-extensionality, and host-answer alternatives are absent from the carrier, so the displayed rows generate the gate-question read.
\end{proof}
