\begin{theorem}[DyadicIntervalNet finite-mesh Real-completion route]
\label{thm:dyadic-interval-net-finite-mesh-real-completion-route}
Every $\DyadicIntervalNetUp$ consumer that routes interval cells into finite dyadic mesh and Real-completion data reads the following displayed rows:
\begin{enumerate}
\item the $\FiniteDyadicMeshUp$ mesh row that groups the dyadic interval cells into a finite subdivision;
\item the $\DyadicRatCoreUp$ arithmetic row that records endpoint, radius, and containment comparisons;
\item the $\StreamNameUp$ finite-window row opened by the displayed mesh request;
\item the $\RegSeqRatUp$ readback row attached to those windows;
\item the terminal $\RealUp$ seal row available only after the preceding rows have been displayed.
\end{enumerate}
No such consumer may replace these rows by open-cover compactness, a selected limit, quotient stream equality, host real equality, countable choice, or ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Project the accepted $\DyadicIntervalNetUp$ carrier. Its cells provide finite dyadic interval data, but a Real-completion consumer still needs an explicit mesh row and dyadic arithmetic ledger before a stream window can be opened.

Read the $\FiniteDyadicMeshUp$ row as the finite subdivision surface and the $\DyadicRatCoreUp$ row as the endpoint and containment ledger. These rows determine the finite window request sent to $\StreamNameUp$.

The $\RegSeqRatUp$ row reads back exactly those windows, and the terminal $\RealUp$ seal is downstream of that readback. The listed rows exhaust the consumer route because the carrier supplies no coordinate for the excluded principles.
\end{proof}
