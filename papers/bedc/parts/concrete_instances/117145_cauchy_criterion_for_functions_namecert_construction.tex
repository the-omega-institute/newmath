\begin{definition}[Cauchy criterion for functions carrier]\label{def:cauchy-criterion-for-functions-carrier}
A $\CauchyCriterionForFunctionsUp$ carrier is a finite $\BHist$ packet
$$
K=(W,T,L,R,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $W$ is the source function-window ledger. It lists the accepted finite argument windows, the displayed $\ContinuousMapUp$ rows available on those windows, and the paired value rows whose tails are compared.
\item $T$ is the uniform tolerance request row. It records one displayed precision request and the single tail threshold demanded for all windows in $W$.
\item $L$ is the pairwise tail-comparison ledger. For every pair of function indices beyond the threshold in $T$ and every displayed source window in $W$, it stores the finite comparison row witnessing that the two value observations are within the requested dyadic tolerance.
\item $R$ is the $\RegSeqRatUp$ readback row for every rational observation exposed by the value comparisons in $L$.
\item $E$ is the terminal $\RealUp$ seal reached only after the function windows, tolerance request, comparison ledger, and regular rational readback have been displayed.
\item $H$ records componentwise $\hsame$ transport for the function-window ledger, tolerance request, pairwise comparison ledger, readback row, real seal, replay, provenance, and local naming row.
\item $C$ records displayed $\Cont$ replay from a uniform Cauchy request through $W,T,L,R,E,H,P,N$.
\item $P$ is the $\Pkg$ provenance over $\CauchyCriterionForFunctionsUp$, $\RealFunctionUniformCauchyUp$, $\ContinuousMapUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\DyadicRatCoreUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\CauchyCriterionForFunctionsUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through the displayed tuple $W,T,L,R,E,H,C,P,N$. The carrier has no coordinate for host function equality, completed function-space equality, quotient streams, selected pointwise limits, countable-choice schedules, ambient real completeness, Lean verification, or bridge checking.
\end{definition}

\begin{theorem}[Cauchy criterion for functions NameCert obligations]\label{thm:cauchy-criterion-for-functions-namecert-obligations}
For every accepted $\CauchyCriterionForFunctionsUp$ carrier
$$
K=(W,T,L,R,E,H,C,P,N),
$$
the local $\NameCert_{\CauchyCriterionForFunctionsUp}$ surface consists exactly of the following finite obligation rows:
\begin{enumerate}
\item carrier admission for the displayed function-window ledger, uniform tolerance request, pairwise tail-comparison ledger, regular rational readback, terminal real seal, transport, replay, provenance, and local name;
\item source-window exposure, requiring every function value used by the criterion to be read from the finite windows listed in $W$;
\item uniform threshold accountability, requiring the threshold row in $T$ to serve all accepted source windows and all compared function-index pairs beyond that threshold;
\item pairwise tail-comparison coverage, requiring every comparison consumed by the criterion to appear in $L$ with its requested dyadic tolerance;
\item regular rational readback, requiring each numeric observation in $L$ to pass through $R$ before the terminal real seal is inspected;
\item Real-seal non-escape, requiring $E$ to remain downstream of $W,T,L,R$ and the structural rows;
\item componentwise stability, requiring replacement along $\hsame$ and displayed $\Cont$ replay to preserve the same finite criterion surface;
\item provenance exhaustion, requiring $P$ to source only the listed rows and to export no host function equality, quotient stream, selected pointwise limit, countable-choice schedule, or ambient real-completeness principle;
\item local naming, requiring $N$ to name exactly this finite criterion surface and no external function-space object.
\end{enumerate}
No local NameCert obligation is stored outside these rows.
\end{theorem}
