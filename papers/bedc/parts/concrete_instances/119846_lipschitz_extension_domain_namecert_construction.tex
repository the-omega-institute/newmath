\chapter{A Concrete Naming Certificate for $\LipschitzExtensionDomainUp$}
\label{ch:concrete-instances-lipschitz-extension-domain-namecert}
\origin{human}

Following Jones, Stein, and Adams--Fournier, the $\LipschitzExtensionDomainUp$ packet names the finite domain-side admissibility data needed before a Lipschitz, Sobolev, trace, compact, or real-valued extension consumer may read a domain as extension-ready. It sits between the bounded-domain certificate of \autoref{ch:concrete-instances-bounded-lipschitz-domain-namecert}, the operator route of \autoref{ch:concrete-instances-lipschitz-extension-namecert}, the Sobolev extension surface of \autoref{ch:concrete-instances-sobolev-extension-operator-namecert}, and the metric, topology, compact, and real rows used by those neighbours. The packet is a domain-level gate, not a selected extension operator, a host trace theorem, a quotient equality of function spaces, or a choice principle.

\begin{definition}[Lipschitz extension domain carrier]
\label{def:lipschitz-extension-domain-carrier}
A $\LipschitzExtensionDomainUp$ carrier is a finite packet
$$
D=(D_0,M,T,L,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $D_0$ is the $\BoundedLipschitzDomainUp$ row, naming the finite boundary-chart, boundedness, and local domain data.
\item $M$ is the $\MetricUp$ row, recording the distance comparisons used by local extension and trace reads.
\item $T$ is the $\TopologyUp$ row, recording membership, neighbourhood, and boundary-open reads.
\item $L$ is the Lipschitz bound row, read through $\LipschitzExtensionUp$ and the sibling Lipschitz rows for every admissible extension request.
\item $E$ is the extension-route row, recording the allowed handoff to $\SobolevExtensionOperatorUp$, $\CompactMetricUp$, and $\RealUp$ support data without selecting a global operator.
\item $H$ records componentwise $\hsame$ transport for $D_0,M,T,L,E,C,P,N$.
\item $C$ records displayed $\Cont$ replay from an extension or trace request through the domain, metric, topology, Lipschitz, and extension-route rows.
\item $P$ is the $\Pkg$ provenance over $\LipschitzExtensionDomainUp$, $\BoundedLipschitzDomainUp$, $\MetricUp$, $\TopologyUp$, $\LipschitzExtensionUp$, $\SobolevExtensionOperatorUp$, $\CompactMetricUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\LipschitzExtensionDomainUp}$ row.
\end{enumerate}
The carrier predicate asserts that every admissible extension-domain read first exposes the bounded Lipschitz domain row $D_0$, then the metric and topology rows $M,T$, then the Lipschitz bound and extension-route rows $L,E$, and finally the transport, replay, provenance, and local naming rows $H,C,P,N$. It has no coordinate for a selected extension operator, host open-set equality, quotient metric equality, completed trace space, or countable choice.
\end{definition}

\begin{theorem}[Lipschitz extension domain NameCert obligations]
\label{thm:lipschitz-extension-domain-namecert-obligations}
For every accepted $\LipschitzExtensionDomainUp$ carrier
$$
D=(D_0,M,T,L,E,H,C,P,N),
$$
the local $\NameCert_{\LipschitzExtensionDomainUp}$ surface consists exactly of the following five obligation rows:
\begin{enumerate}
\item carrier admission for the bounded Lipschitz domain, metric, topology, Lipschitz bound, extension route, transport, replay, provenance, and local naming rows;
\item metric-topology compatibility, requiring distance, membership, neighbourhood, and boundary reads to pass through $M$ and $T$ after $D_0$ is displayed;
\item Lipschitz bound exposure, requiring every extension-ready request to expose the row $L$ before any extension consumer reads a function bound;
\item extension-route admissibility, requiring the row $E$ to route only to displayed $\LipschitzExtensionUp$, $\SobolevExtensionOperatorUp$, $\CompactMetricUp$, and $\RealUp$ support rows;
\item structural stability under $H,C,P,N$, which transports, replays, sources, and names only the displayed finite route.
\end{enumerate}
No domain-level extension obligation is stored outside these rows.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:lipschitz-extension-domain-carrier}. The domain row $D_0$ is the only bounded Lipschitz domain coordinate, and the rows $M,T$ are the only metric and topology coordinates available to a consumer.

Next read the Lipschitz and extension-route rows. The row $L$ records the bound surface that an extension request may inspect, while $E$ records the admissible handoff to the displayed Lipschitz, Sobolev, compact, and real support rows.

Finally attach the structural rows $H,C,P,N$. They transport, replay, source, and name the same finite route, so the carrier has no remaining coordinate from which a selected operator, host open-set equality, quotient metric equality, completed trace space, or choice schedule could be exported.
\end{proof}

\begin{theorem}[Lipschitz extension domain extension-trace route]
\label{thm:lipschitz-extension-domain-extension-trace-route}
Every extension or trace consumer of an accepted $\LipschitzExtensionDomainUp$ carrier must pass through the displayed domain row $D_0$, the metric and topology rows $M,T$, the Lipschitz bound row $L$, the extension-route row $E$, componentwise transport $H$, displayed replay $C$, provenance $P$, and the local $\NameCert_{\LipschitzExtensionDomainUp}$ row $N$ before receiving any extension-domain conclusion. The route may cite the bounded-domain surface of \autoref{ch:concrete-instances-bounded-lipschitz-domain-namecert} and the Sobolev extension surface of \autoref{ch:concrete-instances-sobolev-extension-operator-namecert}, but it exports no host extension operator, trace theorem, quotient function-space equality, ambient compactness, or choice principle.
\end{theorem}
\begin{proof}
Begin with an accepted extension or trace request. Carrier admission forces the request to display $D_0$ first, so the bounded Lipschitz boundary and domain data are read through the sibling bounded-domain certificate rather than a host domain predicate.

The request then reads the metric and topology rows $M,T$. These rows provide the distance, membership, neighbourhood, and boundary-open data that the extension-domain route may use before any Lipschitz estimate is inspected.

Next expose the Lipschitz bound row $L$ and the extension-route row $E$. Together they keep the request inside the displayed Lipschitz and Sobolev extension neighbours, with compact and real support rows available only as named finite packet data.

Finally apply $H,C,P,N$. Transport and replay preserve the same row order, provenance records the permitted sibling sources, and the local NameCert names the domain-level gate. Since no carrier coordinate remains for a selected operator, host trace theorem, quotient equality, ambient compactness, or choice schedule, every accepted consumer must follow the stated route.
\end{proof}
