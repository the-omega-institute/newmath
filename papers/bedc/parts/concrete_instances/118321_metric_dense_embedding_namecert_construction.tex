\chapter{A Concrete Naming Certificate for $\MetricDenseEmbeddingUp$}
\label{ch:concrete-instances-metric-dense-embedding-namecert}
\origin{human}

Following Bourbaki and Kelley on dense embeddings in metric and uniform spaces, the $\MetricDenseEmbeddingUp$ packet records the metric-specific interface by which a source metric carrier enters a target metric carrier as a dense displayed subobject. It sits between the metric embedding surface of \autoref{ch:concrete-instances-metricembedding-namecert}, the uniform dense embedding route of \autoref{ch:concrete-instances-dense-uniform-embedding-namecert}, the completion handoff of \autoref{ch:concrete-instances-completionembedding-namecert}, the metric source of \autoref{ch:concrete-instances-metric-namecert}, the regular rational readback of \autoref{ch:concrete-instances-regseqrat-namecert}, and the terminal real-name boundary of \autoref{ch:concrete-instances-real-namecert}. The packet is a finite NameCert interface for metric density plus graph control; it is not a quotient completion, a selected representative, a host equality of functions, countable choice, or an ambient completeness principle.

\begin{definition}[MetricDenseEmbedding carrier]
\label{def:metric-dense-embedding-carrier}
A $\MetricDenseEmbeddingUp$ carrier is a finite $\BHist$ packet
$$
E=(X,Y,F,D,I,M,R,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $X$ is the source $\MetricSpaceUp$ row, including its metric-distance readback and classifier transport surface.
\item $Y$ is the target $\MetricSpaceUp$ row in which the dense image is inspected.
\item $F$ is the graph row naming the embedding route from displayed source observations to displayed target observations.
\item $D$ is the graph-distance control row, recording the metric comparison budget attached to $F$ without asserting host equality of all distances.
\item $I$ is the dense-image witness: every displayed target ball request is met by a source observation routed through $F$ within the named metric tolerance.
\item $M$ is the $\CompletionEmbeddingUp$ handoff row used by completion-facing consumers after the dense-image witness has been read.
\item $R$ is the $\RegSeqRatUp$ and $\RealUp$ tolerance readback row attached to the metric budget named by $D$ and $I$.
\item $H$ records componentwise $\hsame$ transport for the metric rows, graph row, distance-control row, dense-image witness, completion handoff, tolerance readback, replay, provenance, and local naming rows.
\item $C$ records displayed $\Cont$ replay for the same row order.
\item $P$ is the $\Pkg$ provenance over $\MetricDenseEmbeddingUp$, $\MetricSpaceUp$, $\MetricEmbeddingUp$, $\DenseUniformEmbeddingUp$, $\CompletionEmbeddingUp$, $\RegSeqRatUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\MetricDenseEmbeddingUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through the rows $X,Y,F,D,I,M,R,H,C,P,N$. No coordinate stores quotient completion classes, selected representatives, selected dense points, host function equality, countable choice, or ambient completeness.
\end{definition}

\begin{theorem}[MetricDenseEmbedding NameCert obligations]
\label{thm:metric-dense-embedding-namecert-obligations}
For every accepted $\MetricDenseEmbeddingUp$ carrier $E=(X,Y,F,D,I,M,R,H,C,P,N)$, the local $\NameCert_{\MetricDenseEmbeddingUp}$ surface consists exactly of carrier admission for the two metric rows, graph route, graph-distance control, dense-image witness, completion-embedding handoff, tolerance readback, componentwise transport, displayed replay, provenance, and local naming. Every dense-image read must first inspect $X,Y,F,D,I$ before it can pass to $M,R,H,C,P,N$, and every completion-facing read must preserve that same order.
\end{theorem}
\begin{proof}
Project the accepted carrier of \autoref{def:metric-dense-embedding-carrier}. The packet exposes the source and target metric rows, graph row, graph-distance control, dense-image witness, completion handoff, tolerance readback, and the structural rows, with no further coordinate available.

The dense-image coverage clause is the row $I$. A target ball request is opened inside $Y$, routed back through a source observation in $X$, and then returned along $F$ with the metric budget named by $D$ and read back by $R$.

Transport and replay are structural. The row $H$ moves each displayed coordinate componentwise, and $C$ repeats the same graph-control and dense-image route for later consumers. Since the excluded objects have no carrier coordinate and no replay edge, the listed rows exhaust the local NameCert surface.
\end{proof}

\begin{theorem}[MetricDenseEmbedding completion handoff]
\label{thm:metric-dense-embedding-completion-handoff}
Every completion-facing consumer of an accepted $\MetricDenseEmbeddingUp$ packet $E=(X,Y,F,D,I,M,R,H,C,P,N)$ receives the finite route
$$
X,Y \longrightarrow F \longrightarrow D \longrightarrow I \longrightarrow M \longrightarrow R,H,C,P,N .
$$
The handoff is therefore a metric dense embedding route through graph control, dense-image coverage, and completion embedding data. It never replaces those rows by quotient completion classes, selected representatives, selected limits, host equality, countable choice, or ambient completeness.
\end{theorem}
\begin{proof}
Start from carrier projection. The only completion-facing row is $M$, and it is stored after the source and target metric rows, the graph row, the graph-distance control row, and the dense-image witness.

Use the NameCert obligations of \autoref{thm:metric-dense-embedding-namecert-obligations}. They require any dense-image read to consume $X,Y,F,D,I$ before $M$ or the tolerance readback row $R$ can be used by a downstream completion route.

Finally replay the route through $H,C,P,N$. These rows transport, replay, source, and name the same finite carrier coordinates, so the completion handoff cannot escape into quotient completion equality, selected representatives, host equality of functions, countable-choice selection, or an ambient completeness assumption.
\end{proof}
