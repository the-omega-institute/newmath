\begin{theorem}[Cauchy public L10 export]
\label{thm:cauchy-public-l10-export}
The public $\CauchyUp$ export for L10 consumers is exactly the finite route already established by \autoref{def:cauchy-carrier}, \autoref{thm:cauchy-seed-carrier-boundary}, \autoref{thm:cauchy-filter-modulus-scoped-route}, and \autoref{thm:cauchy-root-regseqrat-real-handoff}: $\StreamNameUp$ windows, $\DyadicRatCoreUp$ tolerance rows, $\RegSeqRatUp$ readback, the terminal $\RealUp$ seal, componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, and the local $\NameCert_{\CauchyUp}$ route. A public consumer receives no quotient stream equality, selected limit, countable-choice schedule, host real equality, quotient completion, or ambient $\RealUp$ completeness coordinate.
\end{theorem}
\leanchecked{BEDC.Derived.CauchyUp.CauchyPublicL10Export}
\begin{proof}
Start with the carrier boundary. \autoref{thm:cauchy-seed-carrier-boundary} exhausts the accepted Cauchy packet by the Cauchy source row, finite windows, dyadic tolerances, regular readback, Real-facing seal, transport, replay, provenance, and local naming.

Use the scoped filter-modulus route. \autoref{thm:cauchy-filter-modulus-scoped-route} shows that filter, modulus, Real-facing, and completion-facing consumers all read the same finite path rather than an external completion object.

Finally apply the root readback handoff of \autoref{thm:cauchy-root-regseqrat-real-handoff}. It places the $\RegSeqRatUp$ readback and terminal $\RealUp$ seal downstream of the same window and tolerance rows. Thus the public L10 export is the displayed route itself, with no additional host equality, selection, choice, quotient, or completeness principle.
\end{proof}
