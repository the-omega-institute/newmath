\begin{theorem}[Cauchy RegSeqRat completion forward route]
\label{thm:cauchy-orphan-forward-completion-route}
Every accepted $\CauchyUp$ read consumed by a completion-facing chapter must pass through the finite $\StreamNameUp$ windows of \autoref{ch:concrete-instances-streamname-namecert}, the $\RegSeqRatUp$ regular-rational readback of \autoref{ch:concrete-instances-regseqrat-namecert}, the terminal $\RealUp$ seal of \autoref{ch:concrete-instances-real-namecert}, and the local $\CauchyUp$ route before completion data is exposed. The route carries only the displayed $\BHist$, componentwise $\hsame$, $\Cont$, $\Pkg$, and local $\NameCert$ rows, and it exports no quotient stream, selected limit, countable-choice schedule, host equality, or ambient $\RealUp$ completeness theorem.
\end{theorem}
\begin{proof}
Start with the Cauchy root sequence and stream routes. They expose finite observations as named windows before any completion-facing consumer can inspect the packet.

Apply the existing Cauchy sibling routes through $\StreamNameUp$, $\RegSeqRatUp$, and $\RealUp$. The read is first a finite stream window, then a regular rational tail budget, and then a real-name seal attached to the same local Cauchy packet.

Finally compose with the Real-completion lattice route. Since the displayed rows contain only $\BHist$, $\hsame$, $\Cont$, $\Pkg$, and local $\NameCert$ data, the completion-facing consumer receives the named forward route without a quotient stream, selected limit, choice schedule, host equality, or ambient Real-completeness coordinate.
\end{proof}
