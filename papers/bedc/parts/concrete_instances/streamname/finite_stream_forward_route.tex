\begin{theorem}[StreamName finite-stream forward route]
\label{thm:streamname-finite-stream-forward-route}
Every finite $\StreamNameUp$ observation section first consumes the finite-stream packet of \autoref{ch:concrete-instances-finite-stream-namecert} before it is reindexed as pointwise StreamName window data. The route reads the finite request list, displayed observation window, componentwise $\hsame$ transport, finite $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert$ row from the $\FiniteStreamUp$ packet, then repacks those rows as the pointwise StreamName window surface used by downstream $\RegSeqRatUp$, $\DyadicRatCoreUp$, and $\RealUp$ consumers. It exports no infinite stream equality, no selected limit, and no ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Start with the finite-stream packet cited in \autoref{ch:concrete-instances-finite-stream-namecert}. Its public rows are finite request, finite observation, transport, replay, provenance, and local naming data.

The StreamName observation section only reindexes those displayed finite rows as pointwise window data. The reindexing changes the consumer-facing window name but does not add a quotient stream, a hidden selector, or an infinite equality principle.

Consequently every downstream read through $\StreamNameUp$ still factors through the same finite packet. Since the input has no coordinate for selected limits or ambient $\RealUp$ completeness, the StreamName route exports none.
\end{proof}
