\begin{theorem}[StreamName finite-window handoff for constructive IVT moduli]
\label{thm:streamname-constructive-ivt-modulus-window-handoff}

The handoff reads the located interval source, opposite-sign witnesses, finite bisection schedule, and dyadic tolerance ledger of the modulus carrier, then opens exactly the endpoint and midpoint windows requested by that finite schedule. It does not claim a completed stream, selected branch, quotient equality, host root selector, countable choice, or ambient completeness.
\end{theorem}
\begin{proof}

Apply the $\StreamNameUp$ finite-window discipline already used by the L10 countable-name gateway. Each observation is a displayed window request in the carrier route, and no completed stream object is produced.

The same windows are then repacked by the $\RegSeqRatUp$ readback row and only afterward reach the $\RealUp$ seal. Since the carrier has no selected branch, quotient-equality, root-selection, choice, or completeness coordinate, the finite-window handoff is the full exported StreamName boundary.
\end{proof}

\begin{theorem}[StreamName finite-request cover pullback]
\label{thm:streamname-finite-request-cover-pullback}
Let a $\ConstructiveIVTModulusUp$ carrier open a finite family of endpoint or midpoint requests during its bisection schedule. Then that family pulls back to a finite $\StreamNameUp$ cover whose $\RegSeqRatUp$ readback rows and terminal $\RealUp$ seal row are unchanged from the original modulus carrier. The pullback only records the displayed request windows, dyadic tolerance rows, regular-rational readback rows, terminal seal, $\hsame$ transport, $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert$ rows; it does not add completed streams, selected branches, quotient equality, countable choice, or ambient completeness.
\end{theorem}
\begin{proof}
Project the finite bisection schedule from the $\ConstructiveIVTModulusUp$ carrier. Its endpoint and midpoint requests form a bounded list because the carrier stores a finite schedule and a displayed dyadic tolerance ledger.

Apply \autoref{thm:streamname-constructive-ivt-modulus-window-handoff} to each request in that list. Each endpoint or midpoint observation is therefore represented by a finite $\StreamNameUp$ window, with no completed stream or branch selector produced.

Collect the resulting windows into one finite cover indexed by the request list. The cover uses the same dyadic tolerance rows as the original schedule, so the $\RegSeqRatUp$ readback rows are the same rows already present in the carrier.

Finally repack the unchanged readbacks into the original terminal $\RealUp$ seal row, carrying along the same $\hsame$, $\Cont$, $\Pkg$, and local $\NameCert$ data. Since no coordinate of the carrier stores quotient equality, countable choice, or ambient completeness, the finite cover is only the pullback of the displayed StreamName windows.
\end{proof}
