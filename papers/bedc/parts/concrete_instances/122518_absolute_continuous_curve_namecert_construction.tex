\chapter{A Concrete Naming Certificate for $\AbsoluteContinuousCurveUp$}
\label{ch:concrete-instances-absolute-continuous-curve-namecert}
\origin{human}

Following Ambrosio--Gigli--Savare and Burago--Burago--Ivanov metric-curve practice, the $\AbsoluteContinuousCurveUp$ packet records absolute continuity of a displayed metric curve by finite interval windows, Real-valued distance estimates, and a partition-sum modulus. It sits between the L10 metric-completion route of $\MetricSpaceUp$ in \autoref{ch:concrete-instances-metric-space-namecert}, the path graph surface of $\ContinuousMapUp$ in \autoref{ch:concrete-instances-continuousmap-namecert}, the Real tolerance ledger of $\RealUp$ in \autoref{ch:concrete-instances-real-namecert}, the partition-control discipline of $\AbsolutelyContinuousFunctionUp$ in \autoref{ch:concrete-instances-absolute-continuous-function-namecert}, the finite length handoff of $\RectifiableCurveUp$ in \autoref{ch:concrete-instances-rectifiable-curve-namecert}, and the scale row of $\ArcLengthParameterUp$ in \autoref{ch:concrete-instances-arc-length-parameter-namecert}. The certificate names the curve-level metric object only through displayed rows; it is not a host path space, a selected representative curve, a measure-completed derivative theorem, or quotient equality of curves.

\begin{definition}[Absolute continuous curve carrier]
\label{def:absolute-continuous-curve-carrier}
An $\AbsoluteContinuousCurveUp$ carrier is a finite $\BHist$ packet
$$
A=(M,I,W,G,D,E,U,R,L,S,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $M$ is the $\MetricSpaceUp$ source row, containing the accepted metric carrier and the distance read used for curve samples.
\item $I$ is the interval row, naming the ordered source interval and its finite endpoint windows.
\item $W$ is the $\StreamNameUp$ parameter-window row recording exactly the sampled subintervals and endpoint requests consumed by the packet.
\item $G$ is the $\ContinuousMapUp$ curve graph row from the displayed interval windows into the metric carrier.
\item $D$ is the $\RealUp$-valued distance-estimate row for adjacent sampled curve values, read only through the metric distance in $M$ and the graph row $G$.
\item $E$ is the partition-sum absolute-continuity modulus row: for each displayed Real error budget it records a finite interval-length budget and the corresponding sum of distance estimates over disjoint sampled subintervals.
\item $U$ is the $\AbsolutelyContinuousFunctionUp$ handoff row, exposing the same partition-budget discipline as a function-level finite ledger when a scalar Real-valued consumer asks for it.
\item $R$ is the $\RectifiableCurveUp$ handoff row, available only after $M,I,W,G,D,E$ have been displayed.
\item $L$ is the $\ArcLengthParameterUp$ compatibility row, pairing accepted length-parameter requests with the same distance-estimate and partition-sum rows.
\item $S$ records componentwise $\hsame$ transport for metric, interval, window, graph, distance-estimate, modulus, rectifiable, arc-length, replay, provenance, and local naming rows.
\item $H$ records displayed $\Cont$ replay from a curve absolute-continuity request through $M,I,W,G,D,E,U,R,L$.
\item $C$ is the $\Pkg$ provenance row over $\AbsoluteContinuousCurveUp$, $\MetricSpaceUp$, $\ContinuousMapUp$, $\RealUp$, $\AbsolutelyContinuousFunctionUp$, $\RectifiableCurveUp$, $\ArcLengthParameterUp$, $\StreamNameUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $P$ is the downstream handoff ledger, recording which of the function-level, rectifiable-curve, and arc-length consumers has read the displayed rows.
\item $N$ is the local $\NameCert_{\AbsoluteContinuousCurveUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through $M,I,W,G,D,E,U,R,L,S,H,C,P,N$. It has no coordinate for host function equality, selected curve representatives, quotient paths, measure-completed derivatives, an ambient path-space completion, countable choice, or bridge evidence.
\end{definition}

\begin{theorem}[Absolute continuous curve NameCert obligations]
\label{thm:absolute-continuous-curve-namecert-obligations}
For the carrier of \autoref{def:absolute-continuous-curve-carrier}, the local $\NameCert_{\AbsoluteContinuousCurveUp}$ surface consists of exactly five obligation rows:
\begin{enumerate}
\item carrier admission for the finite packet $A=(M,I,W,G,D,E,U,R,L,S,H,C,P,N)$;
\item metric-curve exposure through $M,I,W,G,D$, so every distance estimate is read from displayed parameter windows and the accepted metric distance;
\item partition-sum absolute-continuity control through $E$ and the function-level handoff $U$;
\item rectifiable-curve and arc-length compatibility through $R,L,P$ after the same distance-estimate rows have been displayed;
\item componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, local naming, and exclusion of host path spaces, selected representatives, quotient curves, measure-completed derivatives, countable choice, and bridge evidence.
\end{enumerate}
\end{theorem}
\begin{proof}
Project the carrier in \autoref{def:absolute-continuous-curve-carrier}. The rows $M,I,W,G,D,E,U,R,L$ are the whole metric and analytic surface before transport, replay, provenance, handoff bookkeeping, and naming are read.

The metric-curve rows are $M,I,W,G,D$. They expose the accepted metric carrier, the interval and StreamName parameter windows, the continuous curve graph, and the Real-valued distance estimates for adjacent sampled values.

The absolute-continuity row is $E$, with $U$ giving the function-level handoff. A consumer that asks for partition-sum control must read the same finite interval-length budget and the same finite sum of distance estimates before it can use the scalar ledger.

The curve-length rows are $R,L,P$. Rectifiable-curve and arc-length consumers receive only the already displayed distance-estimate packet, together with the handoff ledger recording which consumer route is being used.

Finally $S,H,C,N$ transport, replay, source, and name the same finite packet. Since no carrier coordinate stores a host path space, a selected representative curve, quotient equality of curves, a measure-completed derivative, countable choice, or bridge evidence, the five listed obligations exhaust the local NameCert surface.
\end{proof}

\begin{theorem}[Absolute continuous curve metric-length handoff]
\label{thm:absolute-continuous-curve-metric-length-handoff}
Every metric-completion, rectifiable-curve, or arc-length consumer of an accepted $\AbsoluteContinuousCurveUp$ packet reads the displayed route
$$
\MetricSpaceUp,\ \ContinuousMapUp,\ \RealUp,\ \AbsolutelyContinuousFunctionUp,\ \RectifiableCurveUp,\ \ArcLengthParameterUp
$$
through the finite rows $M,I,W,G,D,E,U,R,L,S,H,C,P,N$. The handoff exports curve-level absolute continuity as a finite metric partition certificate, not as a host path, quotient curve, selected representative, completed path space, measure derivative, or bridge datum.
\end{theorem}
\begin{proof}
Start with the metric and graph rows. The accepted metric carrier $M$ and the continuous graph row $G$ can be read only at the displayed interval and StreamName windows $I,W$.

Next read the numerical control. The row $D$ gives the Real-valued distance estimates for adjacent sampled curve values, while $E$ records the partition-sum modulus that bounds those estimates over finite disjoint subintervals.

Now pass to the sibling consumers. The function-level row $U$ reuses the same partition-control surface, the rectifiable row $R$ reuses the same finite distance-sum ledger, and the arc-length row $L$ reuses the same length-compatible parameter requests.

The structural rows $S,H,C,P,N$ preserve this route by transport, replay, provenance, consumer bookkeeping, and local naming. No step introduces a host path object, quotient equality of curves, selected representative, completed path space, measure-completed derivative, countable-choice schedule, or bridge evidence.
\end{proof}
