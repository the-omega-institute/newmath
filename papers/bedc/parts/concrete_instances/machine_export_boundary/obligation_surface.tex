\begin{theorem}[Machine export boundary obligation surface]
\label{thm:machine-export-boundary-obligation-surface}
Every public $\MachineExportBoundaryUp$ export must pass through the displayed machine-interface, registry-export, audit-provenance, $\hsame$-transport, $\Cont$-replay, $\Pkg$, and local $\NameCert$ rows before any external machine read is public. In particular, the route refines the machine-facing interface of \autoref{ch:concrete-instances-machine-interface-boundary-namecert} and the registry export surface of \autoref{ch:concrete-instances-registry-export-surface-namecert} through the accepted packet $E=(R,T,A,F,H,C,P,N)$.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:machine-export-boundary-carrier}. The target row $T$ supplies the machine-interface surface, while $R$ supplies the registry-export surface before a machine read can be public.

The audit and refusal rows $A,F$ keep provenance-facing evidence and blocked-claim visibility in the same packet. Transport through $H$ and replay through $C$ preserve those displayed rows rather than replacing them with an external machine assertion.

Finally read $P$ and $N$. Package provenance and the local NameCert row close the export boundary only after the machine-interface, registry-export, audit, refusal, transport, and replay rows are visible, so no external read is public outside the displayed obligation surface.
\end{proof}

\begin{theorem}[Machine export boundary bounded diamond consumer]
\label{thm:machine-export-boundary-bounded-diamond-consumer}
Every $\MetaCICBoundedDiamondWindowUp$ consumer of $\MachineExportBoundaryUp$ must read registry status, machine target, audit readback, refusal preservation, componentwise transport, displayed replay, package provenance, and local NameCert rows through the accepted packet $E=(R,T,A,F,H,C,P,N)$ before bounded diamond evidence can be exported. In particular, the bounded-window consumer of \autoref{ch:concrete-instances-metacic-bounded-diamond-window-namecert} may cite the obligation surface of \autoref{thm:machine-export-boundary-obligation-surface} only after all eight rows remain visible in the same machine export boundary packet.
\end{theorem}
\begin{proof}
Project the packet $E=(R,T,A,F,H,C,P,N)$ from \autoref{thm:machine-export-boundary-obligation-surface}. The registry status row $R$, target row $T$, audit row $A$, and refusal row $F$ are the machine-facing data that a bounded diamond consumer must inspect before export.

The structural rows $H,C,P,N$ keep that data inside the accepted packet. Transport and replay preserve the same registry, target, audit, and refusal route, while provenance and local naming keep the route tied to $\MachineExportBoundaryUp$.

Therefore a $\MetaCICBoundedDiamondWindowUp$ consumer cannot export bounded diamond evidence from a bare machine read. It first factors through the displayed MachineExportBoundary obligation surface, with every row of $E$ still visible.
\end{proof}

\begin{theorem}[Machine export boundary bounded diamond packet route]
\label{thm:machine-export-boundary-bounded-diamond-packet-route}
Every bounded-diamond consumer route from $\MachineExportBoundaryUp$ to $\MetaCICBoundedDiamondWindowUp$ must cite \autoref{ch:concrete-instances-metacic-bounded-diamond-window-namecert} through the full accepted machine-export packet $E=(R,T,A,F,H,C,P,N)$. The bounded diamond evidence cannot be read from a bare export row, a detached registry row, or an audit-only machine read; it becomes public only after the registry status, machine target, audit readback, refusal preservation, componentwise transport, displayed replay, package provenance, and local NameCert rows remain visible together.
\end{theorem}
\begin{proof}
Apply \autoref{thm:machine-export-boundary-bounded-diamond-consumer}. It already forces bounded-window consumers to inspect all eight rows of $E$ before machine export can serve bounded diamond evidence.

The chapter route to \autoref{ch:concrete-instances-metacic-bounded-diamond-window-namecert} is therefore a packet route, not a single-row export. Reading only the registry row, only the target row, or only an audit row would omit the refusal, transport, replay, provenance, or naming data required by the accepted MachineExportBoundary surface.

Thus the bounded-diamond dependency edge is carried by the whole packet $E=(R,T,A,F,H,C,P,N)$. A bare export row is not enough to expose bounded diamond evidence to a $\MetaCICBoundedDiamondWindowUp$ consumer.
\end{proof}
