\begin{theorem}[Polish completion criterion NameCert obligations]
\label{thm:polish-completion-criterion-namecert-obligations}
For every accepted $\PolishCompletionCriterionUp$ carrier $K=(X,D,S,Q,L,E,H,C,P,N)$, the local $\NameCert_{\PolishCompletionCriterionUp}$ surface consists exactly of the following obligation rows:
\begin{enumerate}
\item carrier admission for the metric source, dense schedule, stream windows, regular rational readback, displayed limit, Real seal, transport, replay, provenance, and local naming rows;
\item dense schedule stability, requiring every completion-facing observation to preserve the same displayed dense row $D$ under componentwise $\hsame$ transport;
\item Cauchy-thread handoff, requiring the route from $D$ through $S$ and $Q$ to be displayed before $L$ or $E$ is consumed;
\item separated-limit boundary, requiring limit comparison to use the source metric classifier of $X$ together with the displayed limit row $L$;
\item Real-seal nonescape, requiring the Real-facing row $E$ to remain downstream of $D,S,Q,L$ and upstream only of structural rows;
\item ledger refusal for quotient completion equality, selected representatives, countable choice, host real equality, trichotomy, and ambient $\RealUp$ completeness.
\end{enumerate}
No local NameCert obligation is stored outside $X,D,S,Q,L,E,H,C,P,N$.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:polish-completion-criterion-carrier}. The accepted packet displays exactly the metric source, dense schedule, finite windows, regular readback, displayed limit, Real seal, transport, replay, provenance, and naming rows.

The dense schedule stability and Cauchy-thread handoff are read in that order. A completion-facing consumer first opens $D$, then the finite $\StreamNameUp$ windows $S$, and then the $\RegSeqRatUp$ readback $Q$ before the displayed limit $L$ is available.

The separated-limit boundary is supplied by the same metric source $X$ and displayed limit $L$. The Real seal $E$ is downstream of this boundary, so it cannot be used as an ambient completeness source.

Finally $H,C,P,N$ transport, replay, source, and name the same finite route. Since the carrier contains no row for quotient completion equality, selected representatives, countable choice, host real equality, trichotomy, or ambient $\RealUp$ completeness, the ledger refuses those reads.
\end{proof}

\begin{theorem}[Polish completion criterion Cauchy-thread handoff]
\label{thm:polish-completion-criterion-cauchy-thread-handoff}
Every completion-criterion read exported by an accepted $\PolishCompletionCriterionUp$ carrier $K=(X,D,S,Q,L,E,H,C,P,N)$ factors through the dense Cauchy thread
$$

$$
before the terminal $\RealUp$ seal $E$ is consumed. \end{theorem}
\begin{proof}

The Real seal row $E$ is therefore downstream of the displayed Cauchy thread. The structural rows $H,C,P,N$ can transport, replay, source, and name this route, but they do not add quotient completion equality, selected representatives, choice, host real equality, or ambient completeness.
\end{proof}
