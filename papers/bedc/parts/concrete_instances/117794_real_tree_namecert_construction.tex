\chapter{A Concrete Naming Certificate for $\RealTreeUp$}
\label{ch:concrete-instances-real-tree-namecert}
\origin{human}

Following Tits and Morgan on real trees and Bridson--Haefliger on geodesic metric spaces, the $\RealTreeUp$ packet records the finite metric-geometry route by which a uniquely tripod-shaped geodesic metric object is named inside BEDC. It sits beside the metric source of \autoref{ch:concrete-instances-metric-namecert}, the geodesic segment surface of \autoref{ch:concrete-instances-geodesic-metric-namecert}, the hyperconvex comparison packet of \autoref{ch:concrete-instances-hyperconvex-metric-namecert}, the completion boundary of \autoref{ch:concrete-instances-completemetric-namecert}, and the distance readback seal of \autoref{ch:concrete-instances-real-namecert}. The packet names only displayed distance rows, segment witnesses, and branch-point uniqueness ledgers; it is not a host path space, a selected geodesic family, an ambient dendrite, or a global completion theorem.

\begin{definition}[Real-tree carrier]
\label{def:real-tree-carrier}
A $\RealTreeUp$ carrier is a finite $\BHist$ packet
$$
T=(M,G,R,B,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $M$ is the $\MetricUp$ source row, exposing the distance observations available to the packet.
\item $G$ is the $\GeodesicMetricUp$ segment-witness row, recording the finite segment reads that support the tree route.
\item $R$ is the $\RealUp$ distance-readback row for the displayed segment lengths and comparison budgets.
\item $B$ is the branch-point and tripod-uniqueness ledger. It records, for each displayed triple of endpoints, the finite witness that the three segment reads meet in one branch row and that any competing branch row is componentwise identical under the packet classifier.
\item $H$ records componentwise $\hsame$ transport for metric source, segment witnesses, Real readbacks, branch ledgers, continuation rows, provenance, and local naming.
\item $C$ records displayed $\Cont$ replay for distance reads, segment reads, tripod reads, uniqueness checks, and downstream handoffs.
\item $P$ is the $\Pkg$ provenance over $\RealTreeUp$, $\MetricUp$, $\GeodesicMetricUp$, $\HyperconvexMetricUp$, $\CompleteMetricUp$, $\RealUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$ rows.
\item $N$ is the local $\NameCert_{\RealTreeUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through $M,G,R,B,H,C,P,N$. It has no coordinate for a host path space, selected global geodesic family, ambient continuum, quotient tree model, or completion principle.
\end{definition}

\begin{theorem}[Real-tree NameCert obligations]
\label{thm:real-tree-namecert-obligations}
For every accepted $\RealTreeUp$ carrier $T=(M,G,R,B,H,C,P,N)$, the local $\NameCert_{\RealTreeUp}$ surface consists exactly of metric-source admission, geodesic-segment witness exposure, Real distance readback, branch-point and tripod-uniqueness ledger exposure, componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, and local naming. Every consumer of the real-tree packet must factor through
$$
M,G,R,B,H,C,P,N
$$
before it reads a tree-shaped metric datum.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:real-tree-carrier}. The metric source row $M$ supplies the only distance observations, while the segment row $G$ supplies the only geodesic witnesses visible to the packet.

Read the Real distance row $R$ and the branch ledger $B$ next. The row $R$ seals the finite distance budgets, and $B$ records the displayed tripod meeting row and uniqueness comparison for each named triple.

The structural rows $H,C,P,N$ transport, replay, source, and name only those displayed rows. Since the carrier has no coordinate for host paths, selected geodesics, quotient tree models, or ambient completion, the listed rows exhaust the local NameCert obligations.
\end{proof}

\begin{theorem}[Real-tree geodesic-tripod handoff]
\label{thm:real-tree-geodesic-tripod-handoff}
Every boundary, completion, or hyperconvex-style consumer of an accepted $\RealTreeUp$ packet receives only the finite handoff
$$
\MetricUp,\GeodesicMetricUp,\RealUp \longmapsto B,H,C,P,N .
$$
Thus it may inspect displayed distance observations, segment witnesses, Real-valued length reads, and branch-point uniqueness rows, but it cannot import a host path space, a selected family of geodesics, a global hyperconvex hull, or an ambient completion object.
\end{theorem}
\begin{proof}
Start with the metric row $M$ and the geodesic row $G$. These rows are the only source of distance and segment information available to a consumer.

The Real readback row $R$ turns the visible distances into the same finite Real-sealed comparisons used by the sibling $\RealUp$ route. The branch ledger $B$ then supplies the tripod meeting row and uniqueness check for each displayed endpoint triple.

Finally route the handoff through $H,C,P,N$. The hyperconvex and completion siblings may consume the same finite metric rows, but the carrier never exports a host path space, selected geodesic family, global hull, or completion object.
\end{proof}
