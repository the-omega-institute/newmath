Following Peetre and the real interpolation tradition, the $\PeetreKFunctionalUp$ packet names the finite carrier that exposes a $K$-functional request before any interpolation-scale consumer reads it. It sits between the $\NormedSpaceUp$ pair boundary of \autoref{ch:concrete-instances-normedspace-namecert}, the $\RealUp$ value seal of \autoref{ch:concrete-instances-real-namecert}, the $\RegSeqRatUp$ regular readback of \autoref{ch:concrete-instances-regseqrat-namecert}, the $\StreamNameUp$ finite-window discipline of \autoref{ch:concrete-instances-streamname-namecert}, the positive-radius ledger of \autoref{ch:concrete-instances-dyadicratcore-namecert}, and the regularity-scale siblings $\BesovSpaceUp$, $\TriebelLizorkinSpaceUp$, and $\RieszThorinInterpolationUp$ of \autoref{ch:concrete-instances-besov-space-namecert}, \autoref{ch:concrete-instances-triebel-lizorkin-space-namecert}, and \autoref{ch:concrete-instances-riesz-thorin-interpolation-namecert}. The packet records a displayed decomposition budget and value-readback route; it does not assert a quotient interpolation space, selected infimum, countable choice, host norm equality, or ambient $\RealUp$ completeness.

\begin{definition}[Peetre $K$-functional carrier]
\label{def:peetre-k-functional-carrier}
A $\PeetreKFunctionalUp$ carrier is a finite $\BHist$ packet
$$
K=(S,X,T,B,V,Q,W,D,E,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $S$ is the source row naming the interpolation request and the finite expression whose decomposition is inspected.
\item $X$ is the $\NormedSpaceUp$ pair row, displaying the two normed sources used by the request.
\item $T$ is the positive tolerance row for the $K(t,x)$ read, exposed as a finite request rather than a completed infimum.
\item $B$ is the decomposition-budget row listing the finite candidate splits visible to the certificate.
\item $V$ is the value-readback row for the displayed norm-sum comparisons attached to the visible splits.
\item $Q$ is the $\RegSeqRatUp$ regular rational readback row for the finite value windows.
\item $W$ is the $\StreamNameUp$ finite-window row recording which coordinates of the value stream have been inspected.
\item $D$ is the $\DyadicRatCoreUp$ positive-radius ledger controlling tolerance and comparison requests.
\item $E$ is the terminal $\RealUp$ seal row reached only after $S,X,T,B,V,Q,W,D$ are visible.
\item $H$ records componentwise $\hsame$ transport for all displayed rows.
\item $C$ records displayed $\Cont$ replay from the interpolation request through decomposition budget, value readback, regular rational stream, dyadic ledger, Real seal, provenance, and local naming.
\item $P$ is the $\Pkg$ provenance over $\PeetreKFunctionalUp$, $\NormedSpaceUp$, $\RealUp$, $\RegSeqRatUp$, $\StreamNameUp$, $\DyadicRatCoreUp$, $\BesovSpaceUp$, $\TriebelLizorkinSpaceUp$, $\RieszThorinInterpolationUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\PeetreKFunctionalUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through these rows. It has no coordinate for quotient interpolation spaces, selected infima, countable choice, host norm equality, or ambient $\RealUp$ completeness.
\end{definition}

\begin{theorem}[Peetre $K$-functional NameCert obligations]
\label{thm:peetre-k-functional-namecert-obligations}
For every accepted $\PeetreKFunctionalUp$ carrier
$$
K=(S,X,T,B,V,Q,W,D,E,H,C,P,N),
$$
the local $\NameCert_{\PeetreKFunctionalUp}$ surface consists exactly of source admission, $\NormedSpaceUp$ pair exposure, positive tolerance exposure, finite decomposition-budget display, value-readback routing, $\RegSeqRatUp$ regular readback, $\StreamNameUp$ finite-window inspection, $\DyadicRatCoreUp$ radius control, $\RealUp$ sealing, componentwise $\hsame$ transport, displayed $\Cont$ replay, $\Pkg$ provenance, and local naming.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:peetre-k-functional-carrier}. The analytic rows are $S,X,T,B,V,Q,W,D,E$, and the structural rows are $H,C,P,N$.

Read the normed pair and tolerance rows first. The row $X$ displays the two normed sources, while $T$ records the positive request scale. The decomposition row $B$ is therefore a finite budget over displayed candidate splits, not a hidden selector for an extremal split.

Next read the value and completion-facing rows. The rows $V,Q,W,D,E$ carry finite norm-sum comparisons through regular rational readback, stream windows, dyadic radii, and the terminal Real seal. None of these rows supplies quotient equality or ambient completeness.

Finally the transport, replay, provenance, and local naming rows preserve the same finite route. Since no excluded object is a coordinate of the carrier, the local certificate cannot export quotient interpolation spaces, selected infima, countable choice, host norm equality, or ambient $\RealUp$ completeness.
\end{proof}

\begin{theorem}[Peetre interpolation-scale handoff]
\label{thm:peetre-k-functional-interpolation-handoff}
Every Besov, Triebel--Lizorkin, or real-interpolation consumer of an accepted $\PeetreKFunctionalUp$ packet must read the $\NormedSpaceUp$ pair row, positive tolerance row, finite decomposition-budget row, value-readback row, $\RegSeqRatUp$ row, $\StreamNameUp$ finite-window row, $\DyadicRatCoreUp$ ledger, $\RealUp$ seal, and the structural rows before it can route data to $\BesovSpaceUp$, $\TriebelLizorkinSpaceUp$, or $\RieszThorinInterpolationUp$. The handoff exports the finite $K$-functional value route only; it exports no quotient interpolation space, selected infimum, countable-choice schedule, host norm equality, or ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Start with the NameCert obligations of \autoref{thm:peetre-k-functional-namecert-obligations}. They require the rows $S,X,T,B,V,Q,W,D,E,H,C,P,N$ to be read as one packet before any interpolation-scale consumer inspects the endpoint.

The decomposition budget $B$ is downstream of the normed-pair row $X$ and the tolerance row $T$. Thus a consumer first reads the finite pair and request scale, then inspects only the displayed candidate splits.

The value route is completion-facing but finite. The rows $V,Q,W,D,E$ carry the displayed comparisons through regular rational readback, stream windows, dyadic-radius control, and the terminal Real seal before any regularity-scale sibling reads the result.

The structural rows $H,C,P,N$ transport, replay, source, and name the same route. Therefore the consumer receives only the finite $K$-functional handoff and none of the excluded host interpolation claims.
\end{proof}
