\begin{theorem}[CauchySubsequenceSelector regular Cauchy gluing forward route]
\label{thm:cauchy-subsequence-selector-regular-cauchy-gluing-forward-route}
Every $\RegularCauchyGluingUp$ consumer of an accepted $\CauchySubsequenceSelectorUp$ packet must first read the source regular-rational row $R$, the selected finite windows $W$, the monotone selector schedule $M$, and the Cauchy-gap ledger $G$ before gluing compatible selected windows back into a regular Cauchy route. The handoff to \autoref{ch:concrete-instances-regular-cauchy-gluing-namecert} therefore remains a displayed finite-window route rather than a selected representative, quotient stream equality, countable-choice schedule, or ambient Real-completeness principle.
\end{theorem}
\begin{proof}
Project the selector carrier described in \autoref{ch:concrete-instances-cauchy-subsequence-selector-namecert}. Its gluing-facing data are the source row $R$, finite selected windows $W$, monotone selector schedule $M$, and Cauchy-gap ledger $G$.

Only after those rows are visible can a gluing consumer inspect compatible windows. The $\RegularCauchyGluingUp$ route then supplies its own regular-Cauchy compatibility and terminal Real-seal boundary, so the selector packet is a forward dependency of gluing rather than a replacement for the gluing certificate.

Since neither the selector rows nor the gluing route contain quotient stream equality, selected representatives, countable choice, or ambient Real completeness, the composed route exports only the finite selected-window data and the downstream regular Cauchy gluing surface.
\end{proof}
