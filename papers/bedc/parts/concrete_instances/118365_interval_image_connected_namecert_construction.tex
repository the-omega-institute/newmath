\chapter{A Concrete Naming Certificate for $\IntervalImageConnectedUp$}
\label{ch:concrete-instances-interval-image-connected-namecert}
\origin{human}

Following Bishop and Bridges on constructive interval arguments, the $\IntervalImageConnectedUp$ packet records the finite route by which a continuous image of a displayed interval remains connected at the Real-facing certificate boundary. It sits after the continuous image packet of \autoref{ch:concrete-instances-continuous-interval-image-namecert}, the located intermediate-value rows of \autoref{ch:concrete-instances-intermediatevalue-namecert}, the located interval boundary of \autoref{ch:concrete-instances-interval-namecert}, the Darboux-property surface carried by $\DarbouxPropertyUp$, and the terminal real-name seal of \autoref{ch:concrete-instances-real-namecert}. The packet names a constructive interval-image connectedness carrier; it does not assert open-cover compactness, host image-set connectedness, quotient equality of real names, selected preimages, trichotomy, countable choice, or ambient $\RealUp$ completeness.

\begin{definition}[Interval image connected carrier]
\label{def:interval-image-connected-carrier}
An $\IntervalImageConnectedUp$ carrier is a finite $\BHist$ packet
$$
K=(I,F,V,D,L,R,W,Q,H,C,P,N)
$$
with the following displayed rows:
\begin{enumerate}
\item $I$ is the $\LocatedIntervalUp$ source row, including the displayed endpoints, membership ledger, and located interval-window reads.
\item $F$ is the $\ContinuousIntervalImageUp$ row carrying the continuous map, source interval boundary, image-output seal, and finite image-window route.
\item $V$ is the $\LocatedRealIntermediateValueUp$ or $\DyadicIntermediateValueUp$ route used when an image-connectedness request must pass between two displayed Real-facing image values.
\item $D$ is the $\DarbouxPropertyUp$ sibling row, read only as the interval-value handoff induced by the same continuous image route.
\item $L$ records the finite lower and upper image brackets whose endpoints are read through $I,F,V,D$ before a connectedness request is answered.
\item $R$ is the terminal $\RealUp$ seal row for image values, reached only after the interval, continuity, intermediate-value, Darboux, and bracket rows are displayed.
\item $W$ is the $\StreamNameUp$ finite-window row opened for interval endpoints, source probes, image observations, and intermediate-value bisection reads.
\item $Q$ is the $\RegSeqRatUp$ readback row attached to those windows and image-value comparisons.
\item $H$ records componentwise $\hsame$ transport for the interval, continuous-image, intermediate-value, Darboux, bracket, Real seal, finite-window, readback, replay, provenance, and local naming rows.
\item $C$ records displayed $\Cont$ replay through $I,F,V,D,L,R,W,Q,H,P,N$.
\item $P$ is the $\Pkg$ provenance over $\IntervalImageConnectedUp$, $\ContinuousIntervalImageUp$, $\LocatedRealIntermediateValueUp$, $\DyadicIntermediateValueUp$, $\DarbouxPropertyUp$, $\LocatedIntervalUp$, $\RealUp$, $\StreamNameUp$, $\RegSeqRatUp$, $\BHist$, $\hsame$, $\Cont$, and $\NameCert$.
\item $N$ is the local $\NameCert_{\IntervalImageConnectedUp}$ row.
\end{enumerate}
The classifier compares accepted packets only through $I,F,V,D,L,R,W,Q,H,C,P,N$. It has no coordinate for host image subsets, selected preimages, endpoint-choice functionals, quotient real equality, trichotomy, countable choice, open-cover compactness, ambient Real completeness, Lean verification, or bridge checking.
\end{definition}

\begin{theorem}[Interval image connected NameCert obligations]
\label{thm:interval-image-connected-namecert-obligations}
For every accepted $\IntervalImageConnectedUp$ carrier
$$
K=(I,F,V,D,L,R,W,Q,H,C,P,N),
$$
the local $\NameCert_{\IntervalImageConnectedUp}$ surface consists exactly of the following finite obligation rows:
\begin{enumerate}
\item carrier admission for the located interval row, continuous interval-image row, intermediate-value route, Darboux handoff, bracket row, Real seal, finite windows, regular readbacks, transport, replay, provenance, and local naming;
\item interval-source exactness, requiring endpoint, membership, and source-window reads to pass through the displayed $\LocatedIntervalUp$ row $I$;
\item image-route exactness, requiring image-value reads to pass through the $\ContinuousIntervalImageUp$ row $F$ before the connectedness row is inspected;
\item intermediate-value exactness, requiring every between-value request to pass through $V$ and the same displayed image route rather than through host order completeness;
\item Darboux compatibility, requiring $D$ to be read as a sibling route over the same interval and continuous-image rows;
\item Real-seal ordering, requiring $W$ and $Q$ to expose finite StreamName windows and RegSeqRat readbacks before the terminal $\RealUp$ seal $R$ is available;
\item nonescape, excluding host image subsets, selected preimages, endpoint selectors, quotient real equality, trichotomy, countable choice, open-cover compactness, ambient $\RealUp$ completeness, Lean verification, and bridge checking.
\end{enumerate}
No interval-image connectedness obligation is stored outside these rows.
\end{theorem}
\begin{proof}
Carrier admission is projection from \autoref{def:interval-image-connected-carrier}. The accepted packet displays exactly one located interval source, one continuous image row, one intermediate-value route, one Darboux handoff, one bracket row, one Real seal, finite windows, readbacks, and structural rows.

Interval-source exactness is supplied by $I$. Endpoint, membership, and source-window requests have no second source interval coordinate, so each enters the packet through the displayed $\LocatedIntervalUp$ row.

Image-route exactness is supplied by $F$. The continuous interval-image row carries the map, image-output route, and finite image windows before any connectedness request can read an image value.

The between-value route is supplied by $V$ and checked against $D$. These rows expose the located or dyadic intermediate-value handoff and the Darboux sibling surface over the same interval data, so no host order-completeness theorem is substituted.

Finally $L,R,W,Q,H,C,P,N$ impose readback order and local naming. The bracket row is read before the Real seal, StreamName windows and RegSeqRat readbacks precede terminal image-value comparison, and the structural rows contain none of the refused host image, selection, quotient, choice, compactness, completeness, verification, or bridge data.
\end{proof}

\begin{theorem}[Interval image connected intermediate-value route]
\label{thm:interval-image-connected-ivt-route}
Every connectedness read exported by an accepted $\IntervalImageConnectedUp$ carrier factors through
$$
I,F \longmapsto V,D,L \longmapsto W,Q,R,H,C,P,N .
$$
The read uses the located interval source, continuous interval-image route, located or dyadic intermediate-value row, Darboux handoff, bracket row, finite windows, regular readbacks, Real seal, and structural NameCert rows. It does not introduce host image connectedness, selected preimages, open-cover compactness, quotient real equality, trichotomy, countable choice, or ambient $\RealUp$ completeness.
\end{theorem}
\begin{proof}
Start with an accepted packet $K=(I,F,V,D,L,R,W,Q,H,C,P,N)$. The source and image sides are fixed by $I$ and $F$: the located interval row supplies the endpoint and membership boundary, and the continuous interval-image row supplies the image-value route over that same source.

A connectedness request between two displayed image values must then read $V$ and $D$. The intermediate-value row supplies the finite bisection or located crossing route, while the Darboux row records the same interval-value handoff as a sibling route.

The bracket, window, and readback rows are downstream. The row $L$ identifies the displayed image brackets, $W$ and $Q$ expose finite observations and rational readbacks, and $R$ seals the image values as $\RealUp$ names.

The structural rows $H,C,P,N$ transport, replay, source, and name only this route. Since no row stores a host image set, selected preimage, open-cover compactness theorem, quotient real equality, trichotomy, choice, or ambient completeness witness, every connectedness read remains inside the displayed factorization.
\end{proof}

\begin{theorem}[Interval image connected Real seal]
\label{thm:interval-image-connected-real-seal}
Every Real-facing seal read of an accepted $\IntervalImageConnectedUp$ packet is downstream of the interval-image connectedness route. A consumer may inspect the terminal $\RealUp$ row only after it has read the located interval source $I$, the continuous image row $F$, the intermediate-value row $V$, the Darboux handoff $D$, the bracket row $L$, the finite windows $W$, and the RegSeqRat readback row $Q$. The seal exports no ambient Real completeness theorem.
\end{theorem}
\begin{proof}
The carrier definition places the terminal Real seal at $R$ and places $R$ after $I,F,V,D,L,W,Q$ in the displayed reading order. Thus a Real-facing consumer must first inspect the source interval, continuous image route, intermediate-value route, Darboux handoff, bracket row, finite windows, and rational readbacks.

The structural rows do not change that order. They transport, replay, source, and name the same packet, but they contain no coordinate for host real equality, quotient representatives, selected preimages, open-cover compactness, countable choice, or ambient completeness.

Therefore the Real seal is exactly a downstream image-value seal for the displayed finite route, not an independent completeness or host-connectedness principle.
\end{proof}
