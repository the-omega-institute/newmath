\begin{theorem}[Rational interval locator sibling route]
\label{thm:rational-interval-locator-sibling-route}
Every accepted $\RationalIntervalLocatorUp$ read that exports a locator packet consumes the $\DyadicRatCoreUp$ interval endpoint rows, the $\RegSeqRatUp$ finite-window readback rows, and the $\RealSeparabilityUp$ density rows before the locator boundary is available to any downstream consumer. The route records only the finite endpoint, readback, density, transport, replay, provenance, and local naming surface; it exports no host interval, selected dense point, quotient real representative, countable-choice schedule, or ambient $\RealUp$ completeness datum.
\end{theorem}
\begin{proof}
Project the carrier rows of \autoref{def:rational-interval-locator-carrier}. The endpoint rows are the displayed lower and upper rational bounds, while the tolerance and inclusion rows determine which dyadic interval request is being named.

Read the sibling rows in order. The dyadic endpoint data come through \autoref{ch:concrete-instances-dyadicratcore-namecert}, the finite window and readback route comes through \autoref{ch:concrete-instances-regseqrat-namecert}, and the density-facing consumer reads through \autoref{ch:concrete-instances-real-separability-namecert} only after those rows have been displayed.

The structural rows then transport, replay, source, and name the same packet. Since no row contains a host interval, selected dense point, quotient real representative, countable-choice schedule, or ambient Real-completeness witness, the sibling route is exhausted by the listed finite dependencies.
\end{proof}
