\begin{theorem}[RegSeqRat finite tail-window exhaustion]
\label{thm:regular-cauchy-window-exhaustion}
Let $P$ be an accepted $\RegSeqRatUp$ carrier row, let $B$ be a finite displayed $\DyadicRatCoreUp$ tail-budget row for $P$, and let $S$ be a $\StreamNameUp$ pointwise certificate for the same scheduled source. For every finite family of requested dyadic radii carried by $B$, there is a unary threshold $t$ and a finite tail-window ledger such that every request beyond $t$ is witnessed by a pair of $\StreamNameUp$ observations and by $\DyadicRatCoreUp$ common-scale comparison rows before the $\RegSeqRatUp$ readback or downstream $\RealUp$ seal is consumed.

The ledger is a finite BEDC route through $\StreamNameUp$, $\DyadicRatCoreUp$, $\RegSeqRatUp$, $\BHist$, $\hsame$, $\Cont$, $\Pkg$, and $\NameCert$ rows. It exports no quotient stream equality, host real equality, selected limit, countable-choice schedule, metric-completeness datum, completion point, or ambient $\RealUp$ completeness coordinate.
\end{theorem}
\begin{proof}
Induct over the displayed finite family of requested dyadic radii. In the empty case, the accepted packet already supplies the $\StreamNameUp$ schedule, the $\DyadicRatCoreUp$ tail-budget row, the $\RegSeqRatUp$ classifier surface, and the structural $\BHist$, $\hsame$, $\Cont$, $\Pkg$, and $\NameCert$ support.

For the successor step, assume the previous requests have been placed behind a unary threshold and a finite tail-window ledger. Use the pointwise $\StreamNameUp$ certificate to expose the next pair of scheduled observations beyond that threshold.

Next refine the dyadic comparison. The terminal-scale rows of $\DyadicRatCoreUp$ place the new radius and the accumulated budget on one common finite scale, so the next request is represented by displayed endpoint, radius, and comparison rows rather than by a hidden modulus or a selected subsequence.

Apply the tail-halving shift fusion route of \autoref{thm:regseqrat-tail-halving-shift-fusion}. It fuses the transported tail window and the dyadic refinement into a common finite window with the same $\RegSeqRatUp$ readback surface.

Repack the successor ledger by increasing the threshold to cover the new observation pair. The induction invariant is preserved because every step uses only finite StreamName observations, DyadicRatCore common-scale comparisons, the existing RegSeqRat classifier route, and displayed structural rows.

Thus the finite request family is exhausted by a tail-window ledger after a unary threshold. Since no step introduces quotient stream equality, host real equality, selected limits, countable choice, metric completeness, completion points, or ambient Real completeness, the downstream $\RealUp$ seal can read only the displayed finite route.
\end{proof}

\begin{theorem}[RegSeqRat finite tail-window shift exhaustion]
\label{thm:regseqrat-finite-tail-window-shift-exhaustion}
Let $P$ be an accepted $\RegSeqRatUp$ carrier row, let $B$ be a finite displayed $\DyadicRatCoreUp$ tail-budget row for $P$, and let $S$ be a $\StreamNameUp$ pointwise certificate for the same scheduled source. If $P$ is shifted by a displayed finite unary tail, then every retained request is still exhausted by a finite tail-window ledger whose $\StreamNameUp$ window, $\DyadicRatCoreUp$ tolerance rows, $\RegSeqRatUp$ readback, $\RealUp$ seal handoff, $\hsame$ transport, $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert$ rows are the retained rows of the original ledger.

The shift exports no quotient stream equality, host real equality, selected subsequence, countable-choice schedule, metric-completeness datum, completion point, or ambient $\RealUp$ completeness coordinate.
\end{theorem}
\begin{proof}
Begin with the finite tail-window exhaustion theorem, \autoref{thm:regular-cauchy-window-exhaustion}. It supplies a unary threshold and a finite ledger for every displayed family of dyadic radii, with StreamName observations and DyadicRatCore common-scale comparison rows visible before any RegSeqRat or Real handoff.

Shift the regular Cauchy name by the displayed finite unary tail. Retained requests are still beyond a displayed threshold, so the same finite StreamName windows remain the observation rows after dropping the shifted prefix.

Use the StreamName finite-section surface to keep the retained windows inside the same certified source, and use the DyadicRatCore tolerance handoff surface to keep the common-scale tolerance ledger attached to those windows. The RegSeqRat readback and Real seal handoff are therefore replayed through the same $H,C,P,N$ support rows on every retained request.

Repack the shifted route as a finite tail-window ledger. Since the operation discards only the displayed finite prefix and preserves the retained request rows, it cannot add quotient stream equality, a selected subsequence, host equality, choice, metric completeness, completion points, or ambient Real completeness.
\end{proof}

\begin{definition}[RegSeqRat tail-refinement carrier]
\label{def:regseqrat-tail-refinement-carrier}
A finite $\RegSeqRatUp$ tail-refinement packet is a $\BHist$ row
$$
Q=(S,D,T,H,C,P,N)
$$
whose displayed components are: a $\StreamNameUp$ finite request row $S$, a $\DyadicRatCoreUp$ tolerance row $D$, a $\RegSeqRatUp$ tail-window row $T$, componentwise $\hsame$ transport $H$, displayed $\Cont$ replay $C$, $\Pkg$ provenance $P$, and a local $\NameCert$ row $N$. \begin{theorem}[RegSeqRat tail-refinement stability]
\label{thm:regseqrat-tail-refinement-stability}
Let $Q=(S,D,T,H,C,P,N)$ be an accepted finite $\RegSeqRatUp$ tail-refinement packet. Any retained tail request transported by componentwise $\hsame$ and replayed by the displayed $\Cont$ row is represented by the same $\StreamNameUp$ request row, $\DyadicRatCoreUp$ tolerance row, and $\RegSeqRatUp$ tail-window row. Thus tail refinement is stable under the displayed transport and replay surface of $Q$.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:regseqrat-tail-refinement-carrier}. The mathematical data rows are exactly $S,D,T$, while $H$ records componentwise transport for those rows.

Replay the retained request through $C$. Since $C$ is displayed as part of the same packet, it can only replay the finite request, tolerance, and tail-window rows already named by $S,D,T$.

The provenance and naming rows $P,N$ do not add new tail data. Hence every transported retained request remains represented by the same finite tail-refinement surface.
\end{proof}

\begin{theorem}[RegSeqRat tail-refinement Real handoff]
\label{thm:regseqrat-tail-refinement-real-handoff}
Every $\RealUp$ consumer of an accepted finite $\RegSeqRatUp$ tail-refinement packet
$$
Q=(S,D,T,H,C,P,N)
$$
may read only the finite $\RegSeqRatUp$ tail window $T$ together with the $\DyadicRatCoreUp$ tolerance row $D$ and the supporting $\StreamNameUp$ request row $S$. The handoff deliberately exposes finite tail-window and dyadic tolerance data, not quotient stream equality, a selected limit, host real equality, or a completion point.
\end{theorem}
\begin{proof}
Start with a Real-facing read. The request row $S$ displays the finite StreamName window being inspected, and the tolerance row $D$ gives the dyadic scale at which the retained tail request is compared.

Read the tail-window row $T$. It is the only RegSeqRat row exported by the packet, so the Real-facing consumer receives a finite tail-window route rather than a quotient stream object or selected limit.

Finally transport and replay through $H$ and $C$, with $P,N$ recording provenance and local naming. These rows preserve the finite handoff and do not add host real equality, completion points, or ambient Real completeness.
\end{proof}
