\label{def:dyadic-nested-interval-code-carrier}

$$

\item $W$ is the width-shrink ledger, recording the dyadic denominator budget, the exact positive width row, and the displayed shrink comparison for every inspected stage.
\item $S$ is the $\StreamNameUp$ window row exposing the finite stage numbers and endpoint observations that a consumer may read.

\begin{theorem}[Dyadic nested interval code NameCert obligations]
\label{thm:dyadic-nested-interval-code-namecert-obligations}

\end{theorem}
\begin{proof}

The accepted object is exactly the finite packet $D=(I,W,S,R,E,H,C,P,N)$, so every visible row is one of the displayed interval, width, window, readback, seal, transport, replay, provenance, or naming coordinates.

Nested containment stability is read from $I$, while width-shrink exactness is read from $W$. Both rows are dyadic rows, so their endpoint and tolerance data are consumed through the $\DyadicRatCoreUp$ surface named by \autoref{ch:concrete-instances-dyadicratcore-namecert}.

Ledger exactness and nonescape follow by inspection of the carrier. No coordinate stores quotient streams, a choice function, trichotomy, host equality of real names, or an ambient completeness theorem, so no accepted $\NameCert_{\DyadicNestedIntervalCodeUp}$ packet can export those objects.

$$

\end{theorem}
\begin{proof}
