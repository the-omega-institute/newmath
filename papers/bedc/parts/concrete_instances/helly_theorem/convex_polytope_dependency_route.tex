\begin{theorem}[Helly theorem convex-polytope dependency route]
\label{thm:helly-theorem-convex-polytope-dependency-route}
Every accepted $\HellyTheoremUp$ finite-subfamily read displays the $\ConvexSetUp$, $\PolytopeUp$, $\AffineSpaceUp$, $\VecSpaceUp$, and compact finite-read rows before the finite-intersection ledger is consumed. The route may inspect the Helly family row, finite subfamily row, and intersection ledger only after those sibling rows are present; it exports no selected intersection point, ambient separation theorem, quotient affine coordinate, or host compactness oracle.
\end{theorem}
\begin{proof}
Project the Helly carrier of \autoref{def:helly-theorem-carrier}. The convex-family row, finite witness row, ambient row, and finite-intersection ledger are explicit packet coordinates, so a consumer read starts from displayed rows rather than from a host theorem about arbitrary convex families.

Use the sibling dependency files already attached to this chapter. The convex set dependency route supplies the $\ConvexSetUp$ membership and convexity rows, while the convex-polytope lattice route supplies the $\PolytopeUp$ finite-cell witnesses and the $\AffineSpaceUp$ ambient boundary.

The finite convex lattice route adds the $\VecSpaceUp$ scalar row and the compact finite-read rows needed before a finite subfamily can be consumed. With those rows displayed, the Helly ledger reads only the finite-intersection surface carried by the packet.

Finally replay the local transport, provenance, and naming coordinates. They preserve the same finite route and do not add a selected point, separation theorem, quotient affine coordinate, or host compactness oracle. Hence the convex-polytope dependency route is exhausted before the finite-intersection ledger is read.
\end{proof}
