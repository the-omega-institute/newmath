\begin{theorem}[CoveringDimension compact-net dependency route]
\label{thm:coveringdimension-compact-net-dependency-route}
Every root $\CoveringDimensionUp$ read that starts from compact finite-net data must expose the finite cover row, refinement row, order-bound ledger, $\CompactMetricUp$ or $\FiniteEpsilonNetUp$ source, $\MetricCompletionUp$ handoff when completion data are consumed, $\BHist$ carrier, componentwise $\hsame$, displayed $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert_{\CoveringDimensionUp}$ before a dimension-bound consumer may inspect the order row. The route is a compact-net certificate over the accepted carrier $D=(K,E,C,R,O,L,H,T,P,N)$, not an arbitrary open-cover compactness theorem or selected refinement.
\end{theorem}
\begin{proof}
Project the carrier of \autoref{def:covering-dimension-carrier}. The compact metric source $K$, finite epsilon-net row $E$, finite cover row $C$, refinement row $R$, order-bound ledger $O$, and Lebesgue ledger $L$ are displayed before the structural rows are available.

Read the compact-net source through \autoref{thm:coveringdimension-finite-epsilon-net-carrier}. It makes the finite cover row a consequence of the displayed probe bundle and tolerance-indexed coverage witnesses rather than of host compactness.

Then route completion-facing uses through the existing MetricCompletion dependency children. The handoff may consume the same cover and refinement rows, but it does not add a second source for $O$ or a selected completion representative.

Finally $H,T,P,N$ preserve the projected route under transport, replay, provenance, and local naming. This gives the root dependency route as a finite compact-net certificate.
\end{proof}

\begin{theorem}[CoveringDimension refinement-order root route]
\label{thm:coveringdimension-refinement-order-root-route}
For an accepted $\CoveringDimensionUp$ carrier $D=(K,E,C,R,O,L,H,T,P,N)$, the refinement-order root route requires the finite cover row $C$, refinement row $R$, order-bound ledger $O$, $\CompactMetricUp$ or $\FiniteEpsilonNetUp$ source rows $K,E$, any $\MetricCompletionUp$ handoff used by the read, $\BHist$, $\hsame$, $\Cont$, $\Pkg$, and $\NameCert$ to remain visible as one packet before the order bound is exported.
\end{theorem}
\begin{proof}
Start from \autoref{thm:coveringdimension-order-refinement-obligation}. It makes each order count in $O$ depend on the displayed parent and containment witnesses stored in $R$ over the finite cover row $C$.

Use \autoref{thm:coveringdimension-compactmetric-handoff-obligation} to keep $K,E,C,R,O,L$ in the compact metric route. If the consumer asks for completion-facing data, the MetricCompletion child route is inserted after the finite cover and refinement rows and before the order export.

The structural rows $H,T,P,N$ then replay and name the same data. The order-bound ledger is therefore a projected root obligation of the displayed carrier, not parameter transport through an external multiplicity oracle.
\end{proof}

\begin{theorem}[CoveringDimension metric-completion root route]
\label{thm:coveringdimension-metric-completion-root-route}
Every $\MetricCompletionUp$ consumer of a $\CoveringDimensionUp$ bound must first read the finite cover row $C$, refinement row $R$, order-bound ledger $O$, $\CompactMetricUp$ or $\FiniteEpsilonNetUp$ source $K,E$, $\MetricCompletionUp$ handoff, $\BHist$ carrier rows, componentwise $\hsame$, displayed $\Cont$ replay, $\Pkg$ provenance, and local $\NameCert$ row of the accepted packet. The completion boundary receives the displayed finite cover-refinement route; it receives no arbitrary open-cover compactness, host multiplicity theorem, quotient completion point, or selected representative.
\end{theorem}
\begin{proof}
Begin with the compact-net dependency route above. It exposes $K,E,C,R,O,L,H,T,P,N$ before a dimension-bound consumer can inspect the order ledger.

Now insert the completion handoff through the existing MetricCompletion dependency route. The handoff is downstream of the compact metric and finite epsilon-net source rows, so it can replay the cover-refinement certificate but cannot replace it by an ambient completion object.

Finally apply the refinement-order root route. It keeps the order ledger attached to the same finite cover and refinement rows after the completion boundary is visible.

Thus the completion-facing export is a projection and replay of the accepted carrier. It is not parameter transport, quotient topology, selected representatives, or host-level general compactness.
\end{proof}
