\begin{theorem}[Covering dimension finite-cover obligations]
\label{thm:covering-dimension-finite-cover-obligations}
Let $D=(K,E,C,R,O,L,H,T,P,N)$ be an accepted $\CoveringDimensionUp$ packet. Every finite-cover obligation exported by $D$ must first display the $\CompactMetricUp$ source row $K$, the $\MetricUp$ observation route carried by that source, the finite cover row $C$, the refinement row $R$, the order-bound row $O$, and the local $\NameCert_{\CoveringDimensionUp}$ transport, replay, provenance, and naming rows $H,T,P,N$. If the obligation is read by $\RealSeparabilityUp$, $\FiniteEpsilonNetUp$, or $\MetricCompletionUp$, those rows are inserted as finite cover-support rows before the order-bound export and not as ambient compactness or completeness principles.
\end{theorem}
\begin{proof}
Project the accepted carrier. The rows $K,E,C,R,O,L$ are the finite compact-metric cover, finite-net, refinement, order, and compact-cover ledger rows already present in the $\CoveringDimensionUp$ packet.

The metric and downstream support rows are read before export. A $\MetricUp$ observation is available only through the compact metric source row, while $\RealSeparabilityUp$, $\FiniteEpsilonNetUp$, and $\MetricCompletionUp$ supply finite density, finite net, or completion-facing support rows attached to the same cover.

Finally, $H,T,P,N$ transport, replay, source, and name the same finite packet. Since arbitrary open-cover compactness, selected limits, host equality, and ambient completeness are not carrier coordinates, the finite-cover obligation cannot escape the displayed route.
\end{proof}

\begin{theorem}[Covering dimension Real-separability refinement]
\label{thm:covering-dimension-real-separability-refinement}
Every $\RealSeparabilityUp$ refinement read of an accepted $\CoveringDimensionUp$ packet is stable only as a finite-cover route through
$$
\CompactMetricUp,\ \MetricUp,\ \FiniteEpsilonNetUp,\ \RealSeparabilityUp,\ C,\ R,\ O,\ L,\ H,\ T,\ P,\ N .
$$
The refinement may tighten finite cover members and rational or dyadic density windows, but it must preserve the same compact metric source, finite epsilon-net support, refinement membership row, order-bound ledger, compact-cover ledger, and local naming surface. It exports no selected dense sequence, arbitrary open cover, quotient point equality, host dimension theorem, selected limit, or ambient $\RealUp$ completeness assertion.
\end{theorem}
\begin{proof}
Start with \autoref{thm:covering-dimension-finite-cover-obligations}. It places compact metric source data, metric observations, finite cover rows, refinement membership, and order ledgers before any downstream refinement can be consumed.

Read the Real-separability route as finite density data. The $\RealSeparabilityUp$ rows may refine rational or dyadic windows, but the compact metric source $K$ and finite epsilon-net row $E$ remain the cover support used by $C,R,O,L$.

The structural rows $H,T,P,N$ preserve this cover route under componentwise transport and displayed replay. Because no selected dense sequence, arbitrary open cover, quotient point equality, host theorem, selected limit, or ambient completeness row is present, refinement stability is exactly the finite route stated above.
\end{proof}

\begin{theorem}[Covering dimension compact-net order route]
\label{thm:covering-dimension-compact-net-order-route}
Every compact-net order read of an accepted $\CoveringDimensionUp$ packet must pass through $\CompactMetricUp$, $\MetricUp$, $\FiniteEpsilonNetUp$, $\RealSeparabilityUp$, and $\MetricCompletionUp$ support rows before a finite cover order bound is exported. The order row may be consumed only after the finite cover row, refinement row, compact-cover ledger, completion-facing metric row, density row, transport row, replay row, provenance row, and local $\NameCert$ row have been displayed. The route supplies carrier admission and refinement stability, and it does not import open-cover compactness, selected subcovers, selected limits, host equality, quotient completion, or ambient Real completeness.
\end{theorem}
\begin{proof}
Use the finite-cover obligations of \autoref{thm:covering-dimension-finite-cover-obligations}. They expose the compact metric source, metric observations, finite cover, refinement row, order ledger, and structural rows as the carrier boundary.

Insert the compact-net support. The $\FiniteEpsilonNetUp$ row supplies finite centers and coverage witnesses, while the $\RealSeparabilityUp$ row supplies finite density windows; both are read before the order row is public.

For completion-facing consumers, read the $\MetricCompletionUp$ row as displayed metric support for the same finite cover route. It does not add a completed point or quotient completion coordinate.

The order export is therefore downstream of the finite cover, compact-net, separability, completion, transport, replay, provenance, and naming rows. Since the excluded host and choice objects have no carrier slot, the route remains inside finite-cover compactness and selected-limit nonescape.
\end{proof}
